# security — 보안 점검 (제출물은 고치지 않는다 — 결과 문서만 쓴다)

제출물(코드·문서)은 고치지 않는다. 점검 결과만 `docs/security/M<n>.md` 에 쓴다 — 오케스트레이터는 이 탭을 보지 않고 그 문서를 읽는다. 10분 상한.

**보안은 M5 에 처음 보는 것이 아니다.** 아래 7항목은 M2 설계(`docs/ARCHITECTURE.md` 10절 — 항목마다 설계의 답)·M3 브리프 「지킬 것」·검수·오케 자체 점검에서 먼저 지킨다. 기계로 셀 수 있는 1·3·5·7번은 `python3 tools/security_check.py` 가 매번 같은 명령으로 센다. M5 의 이 점검은 최종 확인이다.

## 점검 (각 항목에 통과/지적, 지적은 `파일:줄`)

0. **기계 점검 먼저**: `python3 tools/security_check.py` 출력을 결과 문서 맨 위에 붙인다(FAIL 은 그대로 지적, 「확인 필요」는 아래 항목에서 판정).

1. **시크릿**: `grep -rEn "(sk-|AKIA|ghp_|api[_-]?key|password|secret)\s*[:=]" --include=* .`(`.env.example` 제외) → 값이 코드·커밋·문서·로그에 있나. `.env` 가 git 에 추적되나(`git ls-files .env`).
2. **입력 검증**: 파일 업로드·CSV 파싱·폼 입력에서 빈 값·형식 오류·초대형 입력·경로 조작(`../`)을 어떻게 받나. 깨지는 입력 1개를 실제로 만들어 돌려 본다(결과만 기록).
3. **외부 전송**: 코드가 바깥으로 요청을 보내는 곳(fetch·requests·curl) — 과제 데이터가 밖으로 나가는 경로가 있으면 **즉시 보고**(안내문: 외부 전송 금지·모니터링).
4. **의존성**: 새로 설치한 패키지 목록(`package.json`·`requirements.txt`)과 출처. 설치 없이 되는 것을 설치했나.
5. **권한·실행**: 셸 실행(`exec`·`subprocess`)에 사용자 입력이 들어가나. 서버가 `0.0.0.0` 에 열려 있으면 쓰기 엔드포인트에 검증이 있나.
6. **AI 호출**: 프롬프트에 원본 데이터 전체를 넣나(토큰·유출). 실패 폴백이 있나.
7. **제출물 위생**: 임시 파일·캐시·대형 데이터 복사본·`node_modules` 가 작업 공간에 남았나.

## 출력 형식

```
# security M<n> — <HH:MM>
통과: <항목 번호>
지적 (심각한 순):
- [<항목>] <파일:줄> — <무엇> → <위험> → <최소 수정>
```

오케스트레이터는 지적을 `docs/QNA.md` 약점 지도에 옮기고, 치명적인 것부터 고치고 시간이 남으면 덜한 것도 고친다(양이 많으면 수정 브리프로 워커 탭). 처리 결과를 `decision` 으로.
