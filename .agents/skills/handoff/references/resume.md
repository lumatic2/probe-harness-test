# 세션 교체 — 현재 역할의 작업을 새 세션에서 계속

명시적인 context/컨텍스트 부족·새 세션 요청이면 지금 안전한 중단점에서 실행한다. 같은 실패 2회·응답 지연·compact 반복이면 에이전트가 먼저 제안할 수 있다. 오케는 브리프 발행 직후가 권장 지점이나 사용자 요청을 다음 경계까지 미루지 않는다.

## 오케스트레이터 모드
1. state.md로 `docs/HANDOFF.md`를 갱신한다. 끝낸 것·남은 것·막힌 것·마지막 검증·최근 결정·각 편지함·살아 있는 세션 ID·미처리 메시지·다음 행동을 기록한다. HANDOFF 가 이어받기 정본이다.
2. 자기 변경만 커밋하고 미커밋 타인 작업을 별도 표시한다. 다음 오케에 쓰기 권한을 넘기며 옛 오케는 더 작업하지 않는다. 대기 메시지는 편지함에 있으므로 옛 큐만 뒤지게 하지 않는다.
3. **찬 읽기 점검**: 새 세션이 파일을 읽고 상황·다음 행동·하지 말 것을 말하는 것으로 확인한다. 별도 서브에이전트는 필수가 아니다.
4. 사용자에게 현재 상태·남은 일·아래 문장만 준다. 새 탭 → `codex` → `/model`로 모델·effort 확인 후:

```
AGENTS.md와 roles/오케.md, docs/HANDOFF.md, .agents/skills/handoff/SKILL.md를 읽고 오케를 이어받아. 현재 상황·다음 행동·주의점 3줄을 말하고 이어받기 기록과 새 세션 ID를 등록한 뒤 기존 범위에서 계속해.
```

## 워커 모드 (구현·DM·설명·평가·보안·점검 포함)
1. 현재 편지함 끝에 `인계` 메시지: 끝낸 것·남은 것·막힌 것·마지막 검증·커밋·미커밋 변경·마지막 처리 ID·다음 행동. 이미 존재하는 `src/<모듈>/HANDOFF.md`가 있으면 링크하되 새 중복 요약은 만들지 않는다.
2. 오케에게 인계 알림을 보내고 옛 워커는 쓰기를 멈춘다. 새 워커가 등록하기 전에는 옛 주소에 새 일을 보내지 않는다.
3. 새 탭에 줄 문장을 출력한다:

```
AGENTS.md와 .agents/skills/handoff/SKILL.md, docs/mail/<역할-작업>.md를 읽고 마지막 인계부터 같은 역할로 이어가. 새 세션 ID와 이어받기 답장을 남기고 오케에게 알려줘.
```

## 이어받은 세션

- 파일의 역할·소유 범위를 확인하고 새 세션 ID를 등록한다(mail.md). 오케 교체는 `docs/mail/오케.md`에 새 주소, 워커 교체는 해당 편지함에 새 주소를 추가한다. 이전 주소는 이력으로 남고 최신 등록만 사용한다.
- 마지막 완료·중단·미처리 메시지를 대조한다. 처리 완료한 지시는 재실행하지 않는다. 인계가 모순되거나 옛 세션이 여전히 쓰고 있으면 멈추고 한 줄로 알린다.
- `이어받기 기록`에 이해한 상황·첫 행동·새 주소를 적고 자기 경로로 `git commit -m "handoff: 이어받음 확인"`. 새 승인 없이 진행할 수 있는 기존 범위는 바로 계속하고, 새 사용자 판단이 필요한 것만 묻는다.
- 세션 교체는 새 대화다. `/resume`은 같은 대화 복귀이며 컨텍스트 교체 수단으로 안내하지 않는다. compact 요청만이면 state.md 저장 뒤 `/compact`를 안내한다.
