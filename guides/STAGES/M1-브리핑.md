# M1 브리핑 — 「과제 브리핑해줘」 신호를 받았을 때 (오케스트레이터)

> `roles/오케.md` 「사용자 신호」가 여기를 가리킨다. 이 신호의 턴은 길어지기 쉽다(F1 10분) — 현장 사례 서브에이전트를 먼저 띄우고, 글은 한 번만 쓴다(PROBLEM 을 두 번 쓰지 않는다).

- **「과제 브리핑해줘」** — 시간 앵커는 `setup.sh` 가 이미 `docs/PLAN.md` 에 채웠다(종료 13:00 KST 기준). 계산하지 않는다. 사용자가 「남은 시간 H:MM」을 덧붙였을 때만 `date +%H:%M` 으로 지금을 읽고 종료 = 지금 + 남은 시간으로 다시 계산해 고친다. 앵커 = 종료 기준 세팅·브리핑 끝 −165분 · 문제 확정 −140 · 방향 결정·PLAN −125 · 설계 확정·구현 시작 −105 · 얇은 결과 시연(피드백 DM 1차) −70 · 구현 끝 −50 · 피드백 끝·신규 기능 금지 −25 · 예상 문제 −20 · 사용자 읽기 −10 · 확정 −5(마감선과 버리기 사다리는 `AGENTS.md` 「진행 단계」 — 안내가 아니라 지키는 선이 다섯이다). `docs/PLAN.md` 「시간 앵커」에 적는다(브리핑을 낸 턴에 `date +%H:%M` 으로 첫 줄 「실제 시각」도 채운다). 과제 원문은 스스로 찾는다(작업 공간의 `README.md`·데이터 — 킷 파일 제외, 데이터는 코드로 구조만).
- **먼저 `docs/PROBLEM.md` 첫판을 쓴다**(README·데이터 근거, 모든 줄에 출처 태그). **첫판을 쓰자마자 현장 사례 리서치를 백그라운드로 띄운다**(새 탭 없음 — 오케가 서브에이전트로, 브리핑을 기다리게 하지 않는다): 웹 검색이 되는 서브에이전트 2~3갈래(`guides/RESEARCH.md` 「M1 현장 사례 리서치」, 결과 `docs/research/현장사례-<갈래>.md` — 갈래마다 PLAN 위임 장부에 행을 연다). 같은 업무에서 실제로 터진 문제만 찾고 해법은 찾지 않는다. 서브에이전트는 자동으로 안 뜬다 — 「갈래마다 서브에이전트를 **병렬로 띄우고**, 브리핑은 기다리지 않고 계속 쓴다」라고 **명시**한다.
- 그 뒤 그 내용으로 **과제 브리핑**을 채팅으로 낸다 — 사실만, 해법·아이디어 금지: ① 상황 — 한 줄 제한 없이 이해에 필요한 만큼(누가 무슨 일로 곤란한가) ② 요구 표(요구 · MUST/선택 · README 근거 줄) ③ 제출 조건(필수 파일명·형식·실행 방법) ④ 데이터(파일·행 수·열·결측/중복/단위/기간 경계 이상) ⑤ README 가 말하지 않은 것 — 똑똑함 3층: 넓게 알기(이 일의 앞·뒤를 화살표 한 줄로, README 가 비운 구간) · 엮어 읽기(걸린 사람별 말하지 않았지만 원하는 것 — 근거 줄을 붙이고 없으면 「짐작」) · 먼저 움직이기(모퉁이 너머 터질 문제 2~3개 → PROBLEM 14절). 인터뷰의 씨앗이라 가장 공들인다 ⑥ 시간표(앵커 시각 · 마감선 · 버리기 사다리 — 앞 셋은 지키는 선이라고 적는다). 브리핑은 DM 전 첫판이라 **대화하며 바뀐다고 명시**한다.
- **README 가 짧은 서술형일 때**(코파톤 실물: 역할 한 줄 · 상황 · 현업의 요청(인용) · 현업 파트너 · 과제 · 실행 환경 — MUST 표가 없다) ② 요구 표는 문장에서 뽑는다: 「과제」 절 문장을 하나씩 갈라 **필수 동작**(예: 질문 확인 → 음성 답변 → 돌아보기 — 문장이 「~해야/~할 수 있어야」로 요구하는 것)과 **판단에 맡김**(예: 방식은 자유 · API 활용은 판단에 맡김 — 선택으로 둔다)으로 표를 만들고, 근거 열에는 문장을 그대로 인용한다. 「현업의 요청」 인용과 「현업 파트너」 절(말투·말하지 않을 것)은 ⑤ 의 엮어 읽기 재료다. **「실행 환경」 절을 꼭 읽는다** — OpenAI API 제공(`OPENAI_API_KEY`·`OPENAI_BASE_URL`)이 있으면 제품 안 AI 를 실제로 쓸 수 있다(`AGENTS.md` 「판단 원칙」). 없으면 모의(결정론 폴백)다. 이 줄을 ③ 제출 조건에 적는다. 환경변수 이름은 확인하되 **값은 출력·기록·커밋하지 않는다**.
- 브리핑 끝에 설명 탭 안내 한 줄: `새 탭 → codex → /model 설명 전용 등급 · medium(KICKOFF 세션 편성 표) → 「roles/설명.md 읽고 그대로 해」 → 탭 이름 설명`. 마지막 줄 `다음 입력(오케): (브리핑에 궁금한 것 자유롭게 · 준비되면 「DM 시작하자」)`. 이후 사용자의 자유 질문에 답하고, 답에서 PROBLEM 이 바뀌면 **바뀐 줄만** 고친다. 사용자 답 전엔 구현하지 않는다.
- **질문 통로**: 브리핑 중·DM 이 도는 동안 발견한 업무 질문(README 가 말하지 않은 것 · 14절 모퉁이 너머 · 데이터와 말이 어긋나는 곳)은 `docs/interview/질문후보.md` 에 한 줄씩 남긴다. DM 탭이 시작 때 README·PROBLEM 전체·STRATEGY 를 읽고 회신마다 이 파일을 본다(`roles/DM.md`).
