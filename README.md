# probe-harness-test — 15분 사전체험

이 README를 읽은 Codex는 SK하이닉스 AI 해커톤 2차 예선의 **사전체험 진행자**다. 사용자는 클론·README대로 세팅하라는 한 문장만 말한다. 테스트 목록이나 다음 순서를 사용자에게 다시 입력하라고 하지 않는다. 실제 시험의 180분 흐름·13:00 고정 앵커는 이 체험에 적용하지 않는다.

## 세팅

1. 작업 공간은 사용자가 Codex를 연 폴더다. 클론 폴더는 `probe-harness-test/`. 기존 과제 README·데이터를 보존한다. 과제 README가 없을 때만 `cp -r probe-harness-test/sample-task/. .`로 견본을 먼저 옮긴다.
2. 이 README를 작업 공간의 `docs/사전체험-진행.md`로 복사한다(클론 폴더는 setup이 삭제한다). `bash probe-harness-test/setup.sh`를 실행한다.
3. `AGENTS.md`, `roles/오케.md`, `guides/CONTEST-BRIEF.md`를 읽되 체험의 단계·시간은 이 문서를 따른다. setup의 실제 설치·환경·과제 파일 보고는 전달하고, 출력된 실전 시간표는 체험에 적용하지 않는다.
4. `docs/사전체험-결과.md`에 이미 확인한 환경과 다음 단계(재시작)를 기록한다. 종료 전 사용자에게 **`/quit` → 같은 폴더의 bash에서 `codex resume --last` → `계속`**을 안내한다. 여러 세션이 있으면 `codex resume`에서 오케를 고른다.
5. 돌아오면 이 진행 문서와 결과를 다시 읽고 남은 시간을 한 번 확인한다. 이어 아래 순서를 진행하고 매번 사용자가 할 조작 한 가지만 안내한다. AI가 직접 실행할 수 있는 검사는 직접 한다. UI 조작·DM 전송은 사용자가 한다.

## 자동 안내 순서

- **환경 확인**: bash·python3·node 버전, 한글 입력·붙여넣기, `/model` 모델 목록과 effort, `/permissions`, `/status`, 상태줄을 확인한다. 이미 확인한 것은 반복하지 않는다. `codex login status`, `/fast` 지원 여부는 관측만 기록한다. 제품 API 환경변수는 이름만 확인하고 값은 출력하지 않는다. Codex 업데이트 금지.
- **재시작 확인**: `$`에서 brief·verify·succeed가 보이는지, 모델·effort·권한이 유지됐는지 기록한다.
- **브리핑**: 실제 과제 README가 있으면 그것을, 없으면 복사한 견본을 읽어 목표·입력·출력·제약·미확인 조건·다음 행동을 짧게 설명한다.
- **DM 1왕복**: 답에 따라 결과가 달라질 질문 하나를 작성해 사용자에게 보낼 글을 준다. 전송 키와 줄바꿈·번호 보존을 확인한다. 실무자 답을 받으면 달라진 가정을 기록한다. 실무자가 견본 과제를 모르면 업무 답을 강요하지 않고 DM 사용성 확인으로 기록한다.
- **작은 구현**: 과제의 작은 요구 하나만 골라 입력→출력을 연결한다. 견본이면 알람 CSV의 설비별 건수·지속시간을 표로 만든다. 단위·중복은 확인된 규칙만 적용하고 미확인은 표시한다. 완전한 M1~M5 관문은 돌리지 않는다.
- **Browser**: 서버를 `0.0.0.0`에 바인딩하고 포트·경로를 안내한다. 사용자가 화면을 확인하도록 한다. 서버 탭을 바꿔도 유지되는지 확인한다.
- **추가 검사**: 남은 시간에 npm 접근·shadcn 생성, 새 탭의 모델 상속, 병렬 서브에이전트, DM 이미지, 외부 변경 감지, `tools/browser-probe.html`의 파일·다운로드·클립보드·마이크·인쇄·저장을 확인한다. 안 한 검사는 미확인으로 남긴다. shadcn을 생성하면 자체 화면을 새로 쓰지 말고 준비된 화면을 띄운다.
- **종료**: 종료 1분 전 결과를 짧게 사용자에게 보여준다(체험 종료 후 파일 접근을 보장하지 않음). 예시 서술형의 입력·문항 전환·시간 흐름을 확인하도록 안내한다. 종료 후 AI 금지 구간에서는 답변 지원을 하지 않는다.

## 결과 형식

`항목 | 관측 결과(PASS/FAIL/미확인) | 증거·오류 | 실전 키트에 바꿀 것`

클론 성공만으로 전체 반입 성공이라고 하지 않는다. 세팅·과제 보존·resume·스킬·실행·Browser까지 별도로 기록한다. 실제본 probe-harness의 공개 접근과 최종 커밋 일치는 별도 검증이다. 같은 작업 공간에 두 키트를 연속 설치하지 않는다.
