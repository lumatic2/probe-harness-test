# M4 피드백 — 「피드백 DM 시작하자」 · 「피드백 끝」 (오케스트레이터)

> `roles/오케.md` 「사용자 신호」가 여기를 가리킨다. 회신은 M1 과 같은 **DM 탭**(`roles/DM.md`)이 받는다(`M1-DM.md`). 마감선: 얇은 결과 시연(1차 DM) 11:50 · 신규 기능 금지 12:35. 피드백은 한 번이 아니라 **얇은 결과 → 고친 결과** 두 번 이상 돈다.

- **「피드백 DM 시작하자」**(피드백 브리핑을 두고 오케와 이야기한 뒤 사용자가 친다 — 디자인 검토 전이어도 된다) — **보낼 글을 가장 먼저**: `docs/interview/M4.md` 「질문 1」 = `guides/INTERVIEW.md` ③ 형식(첫 화면 위→아래 실제 값 · 누르는 순서대로 바뀌는 것 · 결과물 원문 앞 10줄) + 성공 기준 대비 숫자(FEEDBACK 1절) + 「어디서 멈추실지 · 빠진 것 · 틀린 숫자」 + **이번에 만든 것 / 안 만든 것과 이유**(범위와 이유를 현업과 합의하는 것도 과제의 일부 — 서면 합의문을 유지한다). 질문 1 을 쓴 뒤 DM 탭에 `이제 M4 야 — docs/interview/M4.md 질문 1 을 보냈어` 를 치라고 안내한다. 이후 DM 탭이 답변 문장을 `요약.md` 에 쌓고 F-ID 로 분류하며 질문을 잇는다. 오케는 `요약.md` 를 읽고 문장마다 `docs/FEEDBACK.md` 3절 F-ID 로 분류(버그·틀린 숫자 = 고침 · 작은 보정 = MUST 안이면 고침 · 새 요구 = 웨이터의 No, 받을지는 사용자 · 확인·칭찬) → 처분과 이유 → 고침은 오케가 직접 또는 해당 모듈 브리프 「재지시」 → 같은 검증 재통과 → **다음 질문에 고친 결과를 다시 보여 준다**. 설명 다섯 칸의 「PROBLEM 빈 절」 자리에 「FEEDBACK 미처분 F-ID」, 관문은 **피드백 관문**(`guides/INTERVIEW.md`). 다 차면 「피드백 끝내도 됩니다」를 권한다. 신규 기능 금지 앵커(12:35)가 오면 관문이 덜 찼어도 남은 것을 README 「안 된다」로 돌리자고 먼저 제안한다.
- **「피드백 끝」**(M4 끝 — 피드백 관문이 찼다고 오케가 권하면 사용자가 판단해 친다) — 끝내기 전에 **독립 재계산**을 한다(아래). 관문을 다시 본다(미충족은 번호와 영향을 한 번 보이고, 그래도 끝이면 `decision`). `feedback` 태그 커밋(PLAN 시간 앵커 실제 시각 채움) → **신규 기능 금지** 확정 → 단계 전환 의식(M4 디브리핑: 실무자가 인정한 성공 기준 · 고친 것 · 받지 않은 것과 이유 · 남은 한계 · 파일 경로 / M5 브리핑) → M5 세 서브에이전트 병렬(보안 ∥ 평가 모드 2 ∥ 제출 점검 동시 — 탭마다 `/model` · 칠 말 · 탭 이름, `M5-제출.md`). 새 요구는 받지 않는다.

## 독립 재계산 (정확성 장치 — M4 끝, `feedback` 커밋 전)

F1 채점의 최대 감점은 계산이 어긋난 채 자기 작성 fixture 로만 통과한 것이었다. 구현 코드를 다시 돌리는 것은 검증이 아니다.
1. 구현 코드와 **별개로** 원본 데이터에서 핵심 숫자 3~5개(전체 건수 · 제외 건수 · 분류 분포 · 최상위 항목 · 기준선 중 성공 기준에 쓰인 것)를 **새로 센다** — 맥락 없는 서브에이전트(프롬프트에 원본 경로 + 규칙 파일 + 센 대상만, 구현 경로는 뺀다)나 짧은 스크립트(`verify` 스킬 「독립 재계산」). 서브에이전트는 **병렬로 띄우고 오케는 기다리는 동안 README 를 정리**한 뒤 결과를 받는다.
2. 구현 결과와 대조해 `docs/VERIFICATION.md` 에 숫자 · 명령 · 일치/불일치를 남긴다. **어긋나면 고친다**(원인이 규칙 해석이면 실무자 확인 질문으로 올리고, 코드 버그면 재지시) → 같은 대조를 다시 통과시킨다.
3. **보류·미분류·제외 비율**: (보류 + 미분류 + 제외) ÷ 전체가 **10% 를 넘으면** 경고하고 실무자에게 묻는다(「이 N건은 이렇게 두는 게 맞나요」 — 목록 일부를 보이며). 넘는데 그대로 가면 `decision` 에 이유를 남기고 README 「안 된다」에 비율을 쓴다.
