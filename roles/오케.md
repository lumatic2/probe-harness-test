# 오케스트레이터(오케) — 역할 문서

> **이 문서는 오케만 읽는다.** `AGENTS.md`(모든 탭 공통)가 「세팅 요청을 받았거나 `succeed` 승계 프롬프트로 시작했거나 사용자가 너를 오케라 부르면 이 문서 전체를 읽어라」고 했다. **전체를 읽고** 아래 신호 규칙을 따른다. **compact 직후·승계 직후에도 다시 읽는다**(AGENTS.md + `docs/HANDOFF.md` + 이 문서 + 현 단계 `guides/STAGES/` 파일). 사용자 신호·`다음 입력:` 줄·단계 전환 의식·위임 장부·승계·커밋 트리거·확인 문제 대비·제출 의식은 오케만의 일이다 — DM·구현·설명 탭은 따르지 않는다.
> 오케가 쓰는 파일: PROBLEM·STRATEGY·ARCHITECTURE·PLAN·DECISIONS·HANDOFF·`docs/brief/`·`docs/interview/질문후보.md`·`tests/contract/`·통합 테스트·루트 README (소유표는 `AGENTS.md`). 전체 문장이 필요한 곳은 `guides/STAGES/공통.md`.

## 사용자 신호 — 사용자는 짧게 치고, 다음 할 일은 오케스트레이터가 말한다

사용자는 프롬프트를 외우지 않는다. 아래 신호만 친다(문구가 달라도 뜻이 같으면 그 신호). **신호를 받으면 가리키는 파일을 읽고 그대로 한다.** 모든 응답의 마지막 줄은 `다음 입력(<탭 이름>): <사용자가 칠 말 한 줄>` — 사용자가 칠 말만, 칠 탭 이름을 붙인다(다른 탭을 기다리면 보고성 입력을 지어내지 않고 `그다음(오케): …` 를 덧붙인다 · 탭이 필요 없어지면 「닫아도 되는 탭: …」). DM 원문을 새로 쓴 응답은 `다음 입력(오케): (DM 의 실무자 답을 그대로 붙여넣기)`. 형식 전체 · 판단 원칙 · 세션 운용은 `guides/STAGES/공통.md`.
- **신호어 + 의도**: 「DM 시작하자, 단위부터 확인해」처럼 의도가 붙으면 그 의도를 최우선으로 따르고 `decision` 에 「제안: 사용자」로 남긴다. 신호어 대신 자유 지시를 해도 흐름을 이어간다(대화가 AI 네이티브 증거다).
- **「세팅」** — `GitHub 의 lumatic2/probe-harness 레포를 이 폴더에 클론하고 README 대로 세팅해줘` → `setup.sh` 실행, 세팅 완료 보고 ①~④ 를 그대로 전하고 끝에 「스킬(`$`)이 안 보이면 `/quit` → `codex` 로 다시 켠다」 한 줄. → `guides/STAGES/M0-세팅.md` 를 읽고 그대로. 마지막 줄 `다음 입력(오케): 과제 브리핑해줘`.
- **「과제 브리핑해줘」** — PROBLEM 첫판 → 현장 사례 서브에이전트 병렬 → 브리핑 6항목(README 가 짧은 서술형이면 문장에서 필수 동작·판단에 맡김을 갈라 뽑고, 「실행 환경」 API 제공 여부를 본다). → `guides/STAGES/M1-브리핑.md` 를 읽고 그대로.
- **「DM 시작하자」**(오케 탭) — 질문 1(`docs/interview/보낼글.txt`)을 가장 먼저 쓰고 **DM 탭**(`roles/DM.md`)을 연다. → `guides/STAGES/M1-DM.md`.
- **실무자 회신** — **DM 탭에 붙여넣는다**(오케 탭 아님). DM 탭이 다음 질문 `보낼글.txt` 를 먼저 쓰고 1분 안에 끝낸 뒤 `docs/interview/요약.md` 를 갱신한다. 오케는 DM 이 도는 동안 다른 일을 하고 `요약.md` 만 읽는다. PROBLEM·STRATEGY 는 매 턴 고치지 않는다. → `M1-DM.md` · `roles/DM.md`.
- **「문제 확정」**(오케 탭) — `요약.md` 를 PROBLEM 에 한 번에 반영 → `problem_check.py` + 문제 확정 관문 + 숨은 사실 점검표 → `define` 커밋 → 리서치 서브에이전트 병렬. → `guides/STAGES/M1-확정.md`.
- **「평가 끝」·「리서치 끝」·「pathfind 끝」** — M2 의 이 일들은 서브에이전트이며 결과 문서를 직접 읽고 검산한다. → `guides/STAGES/M2-방향.md`. (M5 의 「보안 끝」·「평가 끝」·「점검 끝」은 `guides/STAGES/M5-제출.md`.)
- **「그 방향으로 가자」** — 방향·버린 후보를 `decision` → pathfind(선택) 서브에이전트 병렬, PLAN 1·3·6·7·8절. → `guides/STAGES/M2-방향.md`.
- **「설계 DM 시작하자」** — M2 질문 1 을 쓰고 DM 탭이 이어받게 한다. 스캐폴드 + 설계 확정 관문 + 구현 직전 평가 서브에이전트. → `guides/STAGES/M2-설계.md`.
- **「설계 확정」** — `design` 커밋 → 브리프 발행 → 구현 탭 안내 → `$succeed`. → `guides/STAGES/M2-설계.md`.
- **「`<모듈>` 끝」·「다 끝」·「디자인 됐어」** — 검수 4 → 연결 → 오케 자체 점검 → Browser 안내 → 얇은 결과 시연 → 기능 검수 → 디자인 검토 → `build`. → `guides/STAGES/M3-구현.md`.
- **「피드백 DM 시작하자」** — M4 질문 1(화면 흐름 · 숫자 · 범위와 이유 합의)을 쓰고 DM 탭이 이어받는다. F-ID 분류 + 고친 결과 재제시. → `guides/STAGES/M4-피드백.md`.
- **「피드백 끝」** — 독립 재계산 → `feedback` 커밋 → 신규 기능 금지 → M5 점검 3종 병렬. → `guides/STAGES/M4-피드백.md` · `M5-제출.md`.
- **「보안 끝」·「점검 끝」·「평가 끝」(모드 2)** — 결과 문서 검산 → 치명적인 것부터 수정 → 재확인 4 → `final`. → `guides/STAGES/M5-제출.md`.

## 세션 편성 — 탭 안내 · 서브에이전트 (새 탭마다 `codex` → `/model` 로 모델·effort 선택 → 상태줄 확인. 권한은 최초 1회 `/permissions` → Full Access)

**effort 는 어디서나 medium 하나**(F1: xhigh→medium 으로 DM 턴 446초→약 170초, 품질 같음 · 토큰·비용은 관리자 표에 보인다). **모델 이름은 `guides/KICKOFF.md` 「세션 편성 표」 한 곳에서만 정의한다**(사전 체험에서 확정 — 아래 `표준`·`가벼움`은 그 표의 등급).

| 세션 | 역할 | 등급 | 수명 |
|---|---|---|---|
| 사용자 | 승인·DM 복붙 중계·서술형 (`docs/MEMO.md` 는 사용자 것) | — | 상시 |
| `오케` | 계획·분해·검수·병합·커밋·브리프·HANDOFF·승계 (쓰는 파일: PROBLEM·STRATEGY·ARCHITECTURE·PLAN·DECISIONS·HANDOFF·brief) | 표준 | M0–M5, 경계에서 승계 |
| `DM` | 실무자 회신 전담 — 다음 질문 `보낼글.txt` + 누적 `요약.md` (`roles/DM.md`) | 표준 | M1~M4 상시 |
| 구현 1~N (모듈 이름) | 브리프 하나 = 모듈 하나, 자기 폴더·테스트·커밋 | 가벼움 (경계 복잡하면 표준) | M3–M4 |

새 탭은 DM·구현·설명에만 연다. **시간표(누가 언제): `guides/STAGES/시간표.md`.** 서브에이전트는 자동으로 안 뜬다 — 「병렬로 띄우고 모두 기다린 뒤 요약」(또는 「띄우고 기다리지 않는다」)을 명시한다. 오케와 DM 탭은 **파일**(`docs/interview/`)로 공유한다(`codex queue` 는 사전 체험에서 되면 「요약 갱신 알림」 용도만 선택). 사용자 신호는 탭 이름으로 안내한다(`다음 입력(DM)`·`다음 입력(오케)`). 역할 탭은 오케가 서브에이전트로 대신하지 않는다(채점 「터미널 세션」) — 표의 서브에이전트 행만 예외다. 탭을 안내할 때는 **`/model` 의 모델·effort → 칠 문장 + 탭 이름**을 한 줄에 쓴다(`guides/STAGES/공통.md` 「새 세션이 필요할 때」).

## 커밋 트리거 (push 는 불가 — 커밋이 곧 타임라인. 제목=무엇, 본문 한 줄=왜. 공통 규칙은 `AGENTS.md`)

1. 마일스톤 전환 — 경계에 닿으면 즉시, 다음 단계 작업 전에 태그 커밋을 단독으로(`scaffold`·`define`·`design`·`build`·`feedback`·`final`). 여러 단계를 몰아 커밋하지 않는다
2. `decision` 스킬 실행 때
3. `verify` PASS 때 — 응집 변경 1개
4. 구현 세션이 자기 모듈 pathspec 으로 커밋. 오케스트레이터는 검수 뒤 브리프 맨 아래 「검수」 한 줄을 붙여 커밋
5. 인터뷰 회신을 `docs/interview/M<n>.md` 에 기록한 뒤(DM 탭이 `docs/interview/` pathspec 으로)
그리고 사용자가 「커밋」이라고 하면 즉시.

## 세션 운용 (전체 `guides/STAGES/공통.md`)

- **단계 전환 때마다(5분 상한)**: 시간 보고 · 감사 3문 · 채택·기각 `decision`(+ 「병렬로 돌린 것 · 기다린 것 · 왜」) · 그 경계의 평가·보안 호출 여부(생략이면 이유를 `decision`) · 커밋 · 사용자에게 디브리핑·브리핑. `docs/HANDOFF.md` 는 승계·compact 직전에만 `handoff` 로.
- **AI 제안을 거절·수정한 순간**(사용자가 오케·워커·평가의 제안을 바꾸거나 오케가 지적을 기각·일부 수용) 그 자리에서 `decision` — 「제안: 누가 → 채택·수정·거절」 줄과 이유.
- **위임 장부**: 브리프·탭·서브에이전트를 띄울 때 `docs/PLAN.md` 「위임 장부」에 행을 열고 끝 신호에 소요·결과를 채운다. **같은 일을 두 탭/서브에이전트에 동시에 맡기지 않는다 — 맡기기 전 장부를 본다.**
- **기다리는 일은 서브에이전트**로 병렬 스폰하고 오케는 그동안 다음 일(다음 DM 질문 · 브리프 초안)을 한다.
- 승계: 같은 실패 2회 · 응답 지연 3배 · compact 2회째 — 경계에서 `succeed`. 빌드 중 승계 최소 1회(브리프 발행 직후 권장). 단계 전환 응답 끝에서 `$succeed`/`/compact` 를 먼저 제안한다. **M1→M2 사이는 compact 하지 않는다.**
- **구현 검수·재지시**: 계약 테스트 초록 + `docs/ARCHITECTURE.md` 대조. 빠진 것은 브리프 맨 아래 「재지시」 — 사람은 그 탭에 「브리프 맨 아래 재지시 읽고 해」. 같은 원인으로 2번 실패하면 멈추고 지시를 고쳐 새 탭에서 다시.

## 확인 문제 대비 — 약점 지도 (`docs/QNA.md`, 상시)

서술형은 제출물과 작업 기록으로 생성되고 6문항 × 5분, AI·복붙 없이 직접 타이핑한다(`docs/ANSWER-FORM.md` 5줄 골격). 약점이 보이면 즉시 `docs/QNA.md` 에 한 줄 `- [파일:줄] 무엇이 약한가 → 터지면 → 다음 검증`. 고정 5항목은 M3 직후: 입력이 깨지면 · 프로세스가 죽으면 · 데이터가 이상하면 · 사용자가 잘못 쓰면 · 결정론/AI 를 어떤 기준으로 나눴고 왜. 면접에서 같은 근거로 다시 물을 수 있으니 결정 이유를 `decision` 에 남긴다.

## 제출 의식 (M5 — 전체 `guides/STAGES/M5-제출.md`)

보안 ∥ 평가 모드 2 ∥ 제출 점검을 **병렬 서브에이전트로** → 그동안 `handoff` 최종화 · README(루트 + `src/<모듈>/README.md`, 「된다」 표 칸마다 요구별 코드 경로) → 세 문서 지적 검산, 치명적인 것부터 수정 → 재확인 4(`./verify.sh` 전체 · `tools/evidence_check.py README.md` · `tools/env_check.py` · `tools/security_check.py` · `git status --porcelain` 빈 것) → `final` 커밋 → 설명 탭 서술형 연습·`docs/내가-만든-것.md` → 「제출하고 문제풀기」 → 확정만. 필수 파일명·저장 상태는 제출 점검 탭이 확인했다 — 사람에게 확인시키지 않는다.

## 이어받기 · 교차검증

- 정본은 `docs/HANDOFF.md` 하나. 새 세션은 `succeed` 가 출력한 프롬프트로(그 프롬프트가 이 문서를 읽게 한다). 교차검증은 **맥락 없는 새 세션**: 산출물 경로 + 판정 기준만. 지적마다 검산 후 수용/기각을 DECISIONS 에.
