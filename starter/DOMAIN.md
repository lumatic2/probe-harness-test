# 새 과제 데이터로 바꾸는 순서 (화면 코드는 건드리지 않는다)
1. 과제 CSV 의 열 이름·종류를 적는다(번호·제목·상태·우선순위·날짜·담당·그룹·기한 중 무엇인지).
2. `starter/domains/alarm/` 을 `starter/domains/<이름>/` 으로 복사하고 `domain.json` 을 고친다: `app`(이름·한계 문구) · `cols`(열 정의) · `roles`(번호·제목·상태·우선순위·날짜·담당·그룹·기한 열) · `metrics`(지표 카드) · `notice.template`(안내문 틀). 다른 칸은 견본 9개(alarm·education·inspection·documents·interview·yield·purchase·power·transport)을 보고 맞춘다.
3. `node starter/domains/csv-to-sample.mjs <이름> 과제.csv` 로 `sample.json` 을 교체한다(머리글 = 열의 key 또는 label, UTF-8·CP949 자동, 오류 행은 건너뛰고 이유 표시).
4. 고르기: 셸 `/?domain=<이름>` · shadcn `VITE_DOMAIN=<이름> npx vite build`(또는 `/?domain=<이름>`) · 기본값은 `starter/domains/active.json` 의 `active`.
5. 검증: `node --test starter/domains/domains.test.mjs starter/domains/xlsx.test.mjs starter/shell/csv.test.mjs starter/shell/smoke.test.mjs` 통과 → 목록의 내보내기(CSV·엑셀)·D-day 열·안내문 일괄 생성이 새 열로 나오는지 눈으로 1회. 엑셀(`domains/xlsx.mjs`, 의존성 0)은 열 정의의 `type`(number·date)대로 숫자·날짜 칸을 만들고 파일 이름은 `<app.title>-<기준일>-<필터>.xlsx`. 리포트의 「인쇄」는 A4 세로 인쇄 스타일(브라우저 인쇄 → PDF 저장).
6. `cols[].type` 은 text·number·date·enum·person. enum 값마다 `tone`(urgent 옅은 주황 배지 · warn · plain · muted)과 끝난 값의 `done: true` 를 적는다.
7. 선택 설정(있을 때만 켜짐): `control`·`dist`·`matrix` = 위젯 W14 관리도·W15 분포·W16 매트릭스 · `schedule` = 일정 격자 `#/schedule`(자원 열·시간 열·충돌 규칙, 처음 보기 `scale` auto|hour|day — 화면에서 「일 / 주」 전환, shadcn만) · `review` = 문서 검토 `#/review`(태그 분류·불확실 큐) · `assist` = AI 기능 `#/assist`(질문·답변·고정 라벨 판정) · `chat` = 위젯 W17 AI 대화창을 헤더 오른쪽 버튼(옆 패널)으로 연다 — `{"on": true, "title": "버튼·패널 제목", "suggestions": ["첫 질문 칩 2~3개"]}`(키가 없거나 `on:false` 면 버튼이 안 보이고, 위젯 모음의 W17 카드는 어느 도메인에서나 동작, 현재 alarm·interview·yield 만 켜 둠). 칩은 지표 이름을 넣어 쓰면 모의 응답이 그 숫자를 인용한다. `chat.docs: true` = 근거 문서 답변 — `domains/<도메인>/docs/*.md|*.txt`(문서 첫 줄 `# 문서명`, 빈 줄로 문단 구분, `##` 소제목, `>` 줄은 안내라 검색 제외)를 문단으로 쪼개 질문과 가까운 상위 3개만 서버에 싣고, 답 아래 근거 칩(`문서명 §n`)을 누르면 원문이 펼쳐진다(검색 `domains/docs.mjs`, 문서 합계 200KB 안쪽 권장 · 키가 없으면 가장 가까운 문단의 첫 문장을 인용, 못 찾으면 「근거 문서에서 찾지 못했습니다」). 현재 interview(규정 3)·alarm(작업표준 1)만 켜 둠. · `import` = CSV 올리기 `#/import`(`{"maxKB":500}` — 열 맞추기·검증·바꾸기/덧붙이기·되돌리기, 필수 열은 `required`, 기본은 번호 열+날짜 열). · `params` = 기준값 설정 `#/settings`(규칙 값을 `"$param:키"` 로 참조·저장·가정 비교, 계약은 `starter/PARAMS.md`) 칸 설명은 inspection·documents·interview 의 domain.json 을 본다.
8. 위젯 설정 보충: `control.bucket` = `"day"`(기본) | `"hour"`(15분 간격처럼 촘촘한 데이터는 시간 단위 점, 날짜 열이 `YYYY-MM-DDTHH:MM` 꼴일 때) · `heat.where` = metrics 와 같은 `where` 형식으로 히트맵에 셀 행을 거른다(예 `{"status": ["이상"]}`). 「같은 키에서 시간순 연속 이상 칸을 한 구간으로 묶기」는 core 에 넣지 않는다 — 연속 구간은 데이터 열(예 power 의 `run`·`run_len`)로 미리 넣는다. 구간을 묶는 규칙이 과제마다 달라 설정으로 일반화하면 오히려 복잡해진다.
9. 견본 가상 데이터(`domains/` 아래 과제에 안 쓰는 견본 9개 모두 — alarm·education·inspection·documents·interview·yield·purchase·power·transport)는 제출 전에 지운다.
