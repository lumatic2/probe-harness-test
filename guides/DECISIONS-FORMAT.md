# DECISIONS 기입 규약

> `docs/DECISIONS.md`(있으면 그 파일, 없으면 생성)에 결정을 **내린 즉시** 추가한다.
> 기준: 방향을 바꾸는 결정, 범위를 자르는 결정, 대안이 있었던 선택은 전부 기록 대상.

형식 (한 결정 = 한 블록, 3~5줄):

```
## D<번호> — <결정 한 줄> (<시각>)
- 이유: <이 제약에서 왜 이것이 최선인가>
- 기각한 대안: <대안> — <기각 이유>
- 제안: <AI(어느 탭)·사용자·실무자> → <채택·수정·거절>
- 확인: <테스트 이름·통과 수 | 실무자 확인 DM 답변 N | 화면에서 직접 봄 무엇> (선택)
- 영향: <바뀌는 파일·범위> (선택)
```

**확인 세 종류** — ① 테스트(이름과 통과 수) ② 실무자 확인(DM 몇 번째 답) ③ 화면에서 직접 봄(무엇을). 이 셋 중 무엇인지 태그를 단다. 서술형 「확인」 칸이 이 세 종류 중 하나로 채워진다(`docs/ANSWER-FORM.md`).

커밋 메시지에도 같은 원칙을 적용한다 — 제목은 "무엇을", 본문 한 줄은 "왜".
평가·워커·리서치 산출을 받을 때의 처분도 같은 꼴로 남긴다(「제안」 줄이 2차 공식 평가 문구 「AI 제안의 채택·수정·거절 이유」를 받는 자리).
범위 축소도 결정이다: 무엇을 잘랐고 왜 잘랐는지가 남으면, 자른 것 자체가 자원 운용의 근거가 된다.
