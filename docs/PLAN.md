# PLAN.md — 작업 계획서

> 「문제 확정」 뒤 오케스트레이터만 쓴다. PROBLEM 이 「무엇을·왜」, ARCHITECTURE 가 「어떤 구조로」라면 이 문서는 **「무엇부터 · 누가 · 언제 · 어떻게 검증하고 · 늦으면 무엇을 자르나」**다.
> 쓰는 순서: 「문제 확정」 직후 2·4·9절(리서치가 도는 동안 — 방향과 무관) → 「그 방향으로 가자」 직후 1·3·6·7·8절(pathfind 가 도는 동안) → 「pathfind 끝」에 5절 → 설계 DM 회신으로 갱신 → 「설계 확정」에 6·7절 확정. 바뀐 줄은 지우지 않고 취소선으로 남기고 갱신 이력에 적는다(채점: 의도 갱신 및 맥락 유지).
> 쓴 시각: (    ) · 갱신 이력: (HH:MM 무엇이 왜 — `decision` ID)

## 시간 앵커
setup.sh 가 채운다(종료 13:00 KST 기준). 화면 남은 시간과 다르면 오케스트레이터가 고친다(AGENTS.md 「사용자 신호」).

앵커는 안내다 — 지키는 선은 신규 기능 금지·확정 둘. 10분 넘게 늦은 구간은 「조정」 칸에 무엇을 자르거나 당겼는지 적고 `decision` 으로 남긴다.

**채우는 때 (오케스트레이터가, 사람 손 0)**: 각 앵커를 지나는 신호 처리 턴(문제 확정 · 그 방향으로 가자/pathfind 끝 · 설계 확정 · 디자인 됐어 · 피드백 끝 · final 커밋)에서 `date +%H:%M` 으로 「실제 시각」을 쓰고 「차이」(+늦음/−빠름 분)를 계산한다. 「기다리는 동안 한 일」은 그 구간에서 다른 탭이 도는 동안 오케가 한 일(병렬 증거 — 예: 구현 탭이 도는 동안 피드백 DM 질문 준비)을 한 줄로 쓴다. 지어내지 않는다 — 못 쟀으면 「미기록」.

## 위임 장부
「AI 를 얼마나 잘 나눠 썼나」의 증거다. 별도 의식 없이 **기존 순간에 오케스트레이터가 한 줄씩** 쓴다: `brief` 발행·역할 탭 안내·서브에이전트(현장 사례 리서치 등)를 띄울 때 **행을 연다**(시각 · 탭 · 맡긴 일 · 이유 · 예상 소요) → 「<모듈> 끝」·역할 탭 「~ 끝」 신호 때 **실제 소요와 결과를 채운다**. 맡기기 전에 이 표를 본다 — 같은 일을 두 탭/서브에이전트에 동시에 맡기지 않는다. README 「AI 활용 기록」은 이 표와 위 시간 앵커 표를 세어 요약한다.

| 시각 | 탭(역할 · 모델 · effort) | 맡긴 일(브리프·산출 경로) | 이 모델을 고른 이유 | 예상 소요 | 실제 소요 | 결과(통과 / 재작업 N) |
|---|---|---|---|---|---|---|
