# STRATEGY.md — 전략 큰 그림 (문제 쪽만, 해법 없음)

> 오케스트레이터가 「DM 시작하자」 턴에 처음 쓰고, 실무자 회신마다 갱신하는 살아 있는 가설 문서다. 처음 가설이 어떻게 바뀌었는지가 서술형 재료가 된다. **문제 정의서(`docs/PROBLEM.md`) 확정 전에는 해법으로 가지 않는다** — 결과물 모양 가설·결정론/AI 분리 같은 해법 항목은 4번에만 적는다.
> 갱신 이력: (HH:MM 질문 N — 무엇이 왜 바뀌었나)

## 1. 진짜 문제 가설
(1~2개. 브리핑 5번(README 가 말하지 않은 것)과 사용자가 붙여 넣은 메모가 있으면 그것을 엮어서. 근거 줄을 붙인다.)

## 2. 브리핑 이후 바뀐 것
(첫판 가설이 어떤 답변으로 어떻게 바뀌었나 — `답변N` 과 함께. 사용자가 메모를 붙여 넣으면 가설 입력으로 받아 여기서 README·데이터에 비춰 짚는다. 메모는 정답지가 아니다 — 근거 없이 따르지도, 근거 없이 뒤집지도 않는다.)

## 3. 인터뷰로 깨 볼 가정
(가설이 틀릴 수 있는 지점과 묻는 순서. 첫 질문의 근거.)

## 4. 해법 보류함
(떠오른 해법 아이디어·사용자 메모의 매력 요소는 여기 적어만 둔다. 문제 정의서 확정 뒤 방향 결정 대화에서 꺼낸다.)
