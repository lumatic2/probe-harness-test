## 6. 평가 세션이 이 표를 쓰는 법 (제안)

- 모드 1(**구현 직전** — 설계 확정 관문 ㉠·자체 점검이 찬 뒤): **지금까지 진행된 것만** — 2절 전 항목(문제 상황 및 제약 정의 · Output 목표 구체화 · 의도 갱신 · 검증 루프 설계 · 작업 분해·위임 · 재사용 체계)과 1절 「코드 유지보수성」의 구조·경계, 5절 실무자 대화·채택/거절 이유·시간 안배 행을 PROBLEM·PLAN·ARCHITECTURE·스캐폴드·interview·DECISIONS 로 채점. 구현·제출물 항목은 「해당 없음(아직)」이고, 이 설계 그대로 가면 감점될 것만 「앞으로 감점될 것」에 적는다.
- 모드 2(M5): 1~5절 전 항목을 **요건 단위**로 쪼개 채점한다 — 과제 README 요구마다 요건 문장 1개를 직접 만들고(코파톤 요건 문장 꼴: 「A 가 B 로 구현되어 있고 C 가 README 에 문서화」), 증거 좌표 `파일:줄`·테스트 이름·명령을 단다. 증거가 없으면 부분 충족.
- 점수보다 **「부분 충족이 날 칸」 목록**이 산출물이다 — 오케가 그 칸만 고친다.
