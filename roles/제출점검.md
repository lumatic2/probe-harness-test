# 제출 점검 — 역할 문서

오케가 「roles/제출점검.md 읽고 그대로 해」라고 서브에이전트로 띄웠다. 이 문서를 읽고 그대로 한다.

**스킬 경로 (F1 에서 이 점검이 멈춘 원인)**: `submit` 스킬 파일은 **이 작업 폴더의 `.agents/skills/submit/SKILL.md`** 다. `~/.codex/skills/submit/`·홈 `MEMORY.md`·`agent-orchestration` 같은 작업 폴더 밖 경로를 찾지 않는다 — 없다고 멈추지 말고 위 상대 경로를 바로 읽는다. `$submit` 이 안 잡혀도 같다(파일을 직접 읽고 그대로 수행). 점검을 임의로 중단하지 않는다.

## 역할
제출 직전 점검자. 지적 목록만 돌려준다. 고치는 것은 오케스트레이터가 한다. 10분 상한.

## 읽을 파일
`.agents/skills/submit/SKILL.md`(점검 순서 정본) · 과제 README(필수 파일명·형식) · 제출 README · `starter/README-TEMPLATE.md` · `tools/evidence_check.py` · `tools/env_check.py` · `docs/PROBLEM.md` · `docs/VERIFICATION.md` · `docs/PLAN.md`(위임 장부·시간 앵커).

## 할 일
- `submit` 스킬을 순서대로 실행한다: 필수 파일명 · README 증거(루트 `python3 tools/evidence_check.py README.md` + 모듈 `src/*/README.md`) · 교체 지점 표(`python3 tools/env_check.py` → 0) · 낡은 문서 청소 · 클린 재현 · 저장 상태 · 금지 패턴. 각 항목에 통과/지적. 추가로 **README 「AI 활용 기록」 대조 한 줄**: 절이 있고, 탭 수 · 위임 수 · 재작업 수가 `docs/PLAN.md` 「위임 장부」 표 행을 직접 센 값과 같고, 앵커 차이 · 조정이 「시간 앵커」 표와 맞나(다르면 지적 — 고치는 것은 오케).
- 클린 재현의 결과는 `docs/VERIFICATION.md` 에 남긴다. 이 파일과 `docs/judge/점검-<HH:MM>.md` 외에는 아무것도 고치지 않는다.

## 놓친 것 검증
끝내기 전에 스스로 확인한다: ① 스킬의 항목 번호를 하나도 건너뛰지 않았나 ② 「통과」에 실행 출력이 있나(말만으로 통과 처리 금지) ③ 지적마다 파일·줄·최소 수정이 있나.

## 결과 위치
지적 목록(심각한 순)을 `docs/judge/점검-<HH:MM>.md`(파일 이름에 `:` 를 못 쓰는 환경이면 `점검-HH-MM.md`)에 쓰고(오케스트레이터는 채팅을 못 본다 — 파일만 읽는다) 채팅엔 경로를 알리고, 마지막 줄 `■ 점검 완료 — 오케에: 점검 끝 · 이 탭: 닫아도 됨`. 클린 재현 기록만 `docs/VERIFICATION.md`.
