# succeed — 승계 (두 모드)

새 세션은 이 대화를 모른다. 파일만 읽고 다음 행동을 시작할 수 있어야 한다. 누가 불렀는지로 모드를 가른다: 오케스트레이터면 아래 A, 구현 탭(브리프를 받은 워커)이면 B.

## A. 오케스트레이터 모드 (5분 상한)

1. 지금이 마일스톤 경계인지 확인한다. 아니면 가장 가까운 경계까지 간 뒤 한다(치명적 열화면 즉시). 권장 지점: M2 「설계 확정」 뒤 브리프 발행 직후(구현 탭은 브리프만 읽으니 끊기지 않는다) · 승계 기준에 걸리면 M4 끝·M5 전.
2. `handoff` 스킬로 `docs/HANDOFF.md` 를 다시 쓴다. 특히: 구현 세션별 상태(브리프 경로·진행·막힘) · 열려 있는 DM(`docs/interview/M<n>.md` 마지막 순번) · 다음 앵커.
3. 승계 사유를 `decision` 으로: `승계 — 사유 <같은 실패 2회/지연/compact> — <시각>`.
4. **찬 읽기 점검(2분 상한)** — 맥락 없는 서브에이전트에게 「`AGENTS.md` 와 `docs/HANDOFF.md` 만 읽고 ① 지금 상황 3줄 ② 다음 할 일 1개 ③ 하지 말 것 1개를 말하라」를 시킨다. 답이 HANDOFF 와 어긋나거나 「모른다」가 나온 칸은 HANDOFF 를 고친다 — 남이 이어받을 수 있다는 증거다. 결과 한 줄을 HANDOFF 「이어받기 기록」에.
5. 커밋: `git commit -m "handoff: 승계 M<n>" -m "<사유> · 찬 읽기 점검 <맞음/고친 칸>"`.
6. 아래 프롬프트를 채워 **사용자에게 그대로 출력**한다. 사용자는 새 탭에서 `codex` → `/model` Sol 6.1 · xhigh(워커 모드면 그 워커의 모델) → 상태줄 확인 후 붙인다. 이 세션은 더 쓰지 않는다.

```
AGENTS.md 와 docs/HANDOFF.md 를 읽어라 — HANDOFF 가 이어받기 정본이다. 이어서 HANDOFF 「문서 지도」의 파일을 순서대로 읽어라. 너는 오케스트레이터를 이어받는다(사유: <…>). 지금 <HH:MM>, 확정 목표 12:55.
살아 있는 세션: 구현 <n>(브리프: <경로들>). 열린 DM: docs/interview/M<n>.md <순번>.
① 지금 상황 3줄 ② 다음 할 일 1개 ③ 다음 앵커까지 남은 시간 — 말한 뒤 내 확인을 받고 진행하라.
확인을 받으면 HANDOFF 「이어받기 기록」에 시각과 맞았는지·모자랐던 것을 적고 `handoff: 이어받음 확인` 으로 커밋하라.
```

이어받은 세션은 사용자 확인 뒤 「이어받기 기록」을 채우고 커밋한다 — 승계가 실제로 이어졌다는 증거가 파일과 커밋에 남는다.

## B. 워커 모드

1. 자기 루트에 `src/<모듈>/HANDOFF.md` 를 쓴다: 끝낸 것(파일·테스트 이름) · 남은 것 · 막힌 것 · 마지막 검증(명령 → PASS/FAIL, 시각). 실제로 돌려 확인한 것만 적는다.
2. 자기 pathspec 으로만 커밋한다: `git add src/<모듈> tests/<모듈>` 후 `git commit -m "<모듈>: 승계 — <한 줄>"`. 공유 파일은 건드리지 않는다.
3. 아래 프롬프트를 채워 사용자에게 출력한다. 사용자는 새 탭에 붙이기만 한다. 이 탭은 더 쓰지 않는다.

```
AGENTS.md · docs/brief/<모듈>.md · src/<모듈>/HANDOFF.md 를 읽고 이어가라.
```

## 금지
- HANDOFF 에 확인 안 한 숫자·없는 파일을 쓰지 않는다(`ls`·`git log -1`·VERIFICATION 마지막 줄로 확인).
- 승계 뒤 두 세션이 같은 파일을 동시에 쓰지 않는다 — 옛 세션은 닫는다.
- 워커 전용 스킬을 따로 만들지 않는다 — 이 스킬 하나로 한다.
