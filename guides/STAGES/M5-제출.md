# M5 검증·제출 — 「보안 끝」·「평가 끝」(모드 2)·「점검 끝」 · 제출 의식 (오케스트레이터)

> `roles/오케.md` 「사용자 신호」·「제출 의식」이 여기를 가리킨다. 마감선: 확정 12:55. M5 의 세 점검(보안 · 평가 모드 2 · 제출 점검)은 오케가 **병렬 서브에이전트**로 띄운다(새 탭 없음 — 꼭 새 탭이 필요한 것만 탭: 수정 워커). 시간표 `guides/STAGES/시간표.md`.

## 세 서브에이전트와 결과 처리

- M5 세 서브에이전트(「피드백 끝」 직후 오케가 띄운다): 「병렬로 띄우고 모두 기다린 뒤 요약」을 명시해 — 보안(`roles/보안.md` → `docs/security/M5.md`) · 평가(`roles/평가.md` 모드 2 → `docs/judge/모드2-*.md`, `docs/QUESTIONS.md`) · 제출 점검(`roles/제출점검.md` → `docs/judge/점검-*.md`, 가벼움 등급으로 낮춰 지정; 등급별 모델은 KICKOFF 세션 편성 표). 스킬이 `$` 로 안 잡히면 `.agents/skills/<이름>/SKILL.md` 를 직접 읽고 그대로 한다(`~/.codex/skills/` 에서 찾지 않는다). 오케는 기다리는 동안 `handoff` 최종화 · README · 약점 지도를 한다.
- **「보안 끝」·「평가 끝」·「점검 끝」**(M5 세 서브에이전트 — 「보안 끝」 `docs/security/M5.md` · 「평가 끝」 모드 2 `docs/judge/모드2-*.md` · 「점검 끝」 `docs/judge/점검-*.md` — 끝나는 순서대로): **결과 문서를 직접 연다.** 지적마다 검산 → **치명적인 것부터** 고친다(제출 실패 · 틀린 결과 숫자 · 시크릿·외부 전송 · README 가 실물과 다름). 덜한 것도 시간이 남으면 고친다 — 순서는 심각도, 같으면 고치는 비용이 작은 것부터. 양이 많으면 오케가 다 하지 않고 수정 브리프(`docs/brief/수정-<HH:MM>.md` — `brief` 스킬 형식, 지적 ID · 고칠 파일 범위 · 같은 검증 명령)를 발행해 새 워커 탭(`/model` 가벼움 등급 · medium → 「docs/brief/수정-<HH:MM>.md 읽고 그대로 해」 → 탭 이름 수정)에 맡기고, 오케는 나머지와 검산을 한다. 신규 기능 금지는 그대로다 — 고침이지 기능 추가가 아니다. 못 고친 것은 README 「안 된다」·`docs/QNA.md` 로 · 처분은 `decision`. 세 문서 처분이 끝나면 재확인 4(`./verify.sh` 전체 · `python3 tools/evidence_check.py README.md` · `python3 tools/security_check.py` · `git status --porcelain` 빈 것) → `final` 커밋(PLAN 시간 앵커 실제 시각 채움 · README 「AI 활용 기록」 절은 이 커밋 전에 PLAN 표를 세어 쓴다) → 마지막 줄 `다음 입력(설명): 서술형 연습하자` + `그다음: 「내가 만든 것 한 장」 읽고 외우기 → 화면 「제출하고 문제풀기」 → 확정`. 결과 문서는 오케가 커밋한다.

## 제출 의식 (M5)

1. 보안(`roles/보안.md`) ∥ 평가 모드 2(`roles/평가.md`) ∥ 제출 점검(`roles/제출점검.md`) — 병렬 서브에이전트로 동시
2. 그동안 `handoff` 최종화(실물과 다른 숫자·없는 파일 언급 0개) · README = 루트 `README.md`(`starter/README-TEMPLATE.md` — 「AI 활용 기록」 절은 오케가 PLAN 위임 장부·시간 앵커 표를 세어 5~8줄로 채운다) + 모듈마다 `src/<모듈>/README.md`(구현 탭이 브리프대로 쓰고 검수에서 확인), 「된다」 표의 칸마다 증거(요구별 코드 경로 포함)
3. 세 결과 문서(`docs/security/M5.md` · `docs/judge/모드2-*.md` · `docs/judge/점검-*.md`) 지적 검산 → 치명적인 것부터 수정, 시간이 남으면 덜한 것도(양이 많으면 수정 브리프로 워커 탭 · 못 고친 것은 README 「안 된다」·QNA)
4. 재확인 4(README 「AI 활용 기록」 숫자 ↔ PLAN 표 대조 포함) — `./verify.sh` 전체 PASS · `tools/evidence_check.py README.md` 0 · `tools/env_check.py` 0(환경 변수 표 빠짐 없음) · `tools/security_check.py` 0 · `git status --porcelain` 빈 것
5. `final` 커밋
6. 평가 서브에이전트가 `docs/QUESTIONS.md` 를 최종 커밋 기준으로 쓰고, **설명 탭**이 그 문항으로 서술형 연습을 시킨다 — 사용자는 `docs/내가-만든-것.md` 를 읽고 외운다. 서술형 뒤 **면접에서 같은 근거로 다시 물을 수 있다**(채점기가 맞춤 면접 질문을 만든다) — 결정 이유를 내 말로 설명할 수 있게 `docs/ANSWER-FORM.md` 5줄 골격으로 공부한다
7. 사람은 「제출하고 문제풀기」 → 확정만. 필수 파일명·README·저장 상태(`git status` 깨끗)는 제출 점검이 이미 확인했다 — 사람에게 확인시키지 않는다
