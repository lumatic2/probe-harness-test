# docs/QUESTIONS.md 생성 양식 (평가 세션이 M5 모드 2 에서 `final` 커밋 뒤 만들고 사용자에게 설명한다)

목적: 후속 서술형(6문항×5분)을 사용자가 미리 읽고 답을 몸에 익히게 한다. 답 틀은 `docs/ANSWER-FORM.md`.

## 출력 양식
머리말(맨 위 3줄):
- 생성 시각: <YYYY-MM-DD HH:MM> · 커밋 해시: <git rev-parse --short HEAD> · 읽는 데 10분

문항 6개 이상(상한 없음 — 약점·결정마다 더 낸다), 각 문항은 아래 형식 그대로:

```
### Q<n> — <질문 한 줄>
- 지점: <파일:줄>, <파일:줄>   (2개 이상, 실제 존재하는 줄)
- 답: <ANSWER-FORM 5줄 골격, 400~500자 — 판단 → 지점 2개 이상(각각 → 파급) → 확인(또는 한계) → 다음. 사용자가 손으로 칠 글이라 파일 경로·백틱·코드 없이 부품을 우리말로>
- 외울 이름: <3~5개 — 부품의 우리말 이름(확실한 함수 이름은 괄호로 하나) · 숫자(행 수·테스트 개수·기준 값)>
- 관련 파일: <경로들>
```

## 질문 생성 규칙
- 재료는 제출물 코드, 커밋 로그, `docs/QNA.md`, `docs/DECISIONS.md` 에서만 쓴다. 그 밖의 지식으로 만들지 않는다.
- 유형 배분: 운영 장애 2 · 설계 경계(결정론/AI 분리) 2 · 검증 가능성 1 · 가장 약한 지점 1. 실물 질문 예시가 하나뿐이라 한 모양에 몰지 않는다 — 그 뒤 문항은 아직 안 쓴 유형(포기한 것 · 전제 오류 · 문서-코드 불일치 · 반증 조건 · AI 보고 검증 · 이어받기 · 도구 선택 · 시간 안배)에서 고른다. 질문은 괄호에 부품 이름 2~3개를 짚는 실물 모양으로 쓴다.
- 일반론 질문 금지. 질문마다 코드의 특정 파일·함수에 닿아야 한다.
- 「답」은 ANSWER-FORM 5줄 골격을 따르고, 안 한 일·없는 기능은 쓰지 않는다.
- 「외울 이름」에 적은 말은 「답」 본문에 반드시 들어간다(생성 뒤 grep 으로 확인). 「지점」의 `파일:줄` 은 공부 때 근거를 보여 주는 용도이고 답에는 넣지 않는다.
- 「지점」의 파일:줄은 생성 직후 열어 실제 내용과 맞는지 확인한다.
