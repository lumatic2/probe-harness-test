# M3 구현 — 「`<모듈>` 끝」 · 기능 검수 · 「다 끝」 · 「디자인 됐어」 (오케스트레이터)

> `roles/오케.md` 「사용자 신호」가 여기를 가리킨다. 마감선: 구현 시작 늦어도 11:15 · **얇은 결과 시연(피드백 DM 1차) 11:50**. 구현은 새 탭(오래 도는 일)이고, 오케는 기다리는 동안 다음 일을 한다.

- **「`<모듈>` 끝」**(구현 탭 마지막 줄을 사용자가 옮겨 침) — `brief` 스킬 「수신」대로 검수 4 → 통과 기록 또는 재지시(PLAN 위임 장부 실제 소요·결과 채움). 기다리는 동안 오케스트레이터는 모듈 연결 코드 · README 「된다」 표 뼈대(요구마다 **코드 파일 경로** — 채점기가 요구 → 코드 파일을 짚는다) · `QNA.md` 고정 5항목 · M4 피드백 DM 초안을 한다. **같은 원인으로 2번 실패하면 멈추고 지시(브리프)를 고쳐 다시 보낸다** — 같은 말을 되풀이하지 않는다. 지시를 내리기 전에 검증 방법(완료 조건의 실행 가능한 명령)이 브리프에 먼저 있어야 한다.
- **모든 모듈이 통과하면** 연결 코드 → 통합 테스트 초록 → **오케 자체 점검**(모듈을 엮어 돌아가는 서비스로 만들고 버그를 잡는 것은 오케 몫 — 사용자 지적은 최소로): 서버를 띄워 경로마다 `curl` 응답 · 눌러 볼 순서마다 대응 테스트나 명령 · 실제 데이터로 PLAN 8절 숫자 · 빈·오류 입력(ARCHITECTURE 9·10절) · `python3 tools/env_check.py`(코드가 읽는 환경 변수 ↔ README 표 — 빠짐 0) · `python3 tools/security_check.py` · 클린 재현 한 번(`submit` 스킬 5번 — M5 에서 처음 터지지 않게) → 찾은 버그는 오케가 고치거나 그 모듈에 재지시 → 같은 검증 재통과 → **Browser 안내**: `guides/BROWSER.md` 를 읽고 「사람에게 줄 안내」를 한 덩어리로 낸다 — `서버` 탭(Codex 아닌 맨 터미널 탭, 닫지 않는다)에 칠 실행 명령(`0.0.0.0` 바인딩) · PORT · URL 경로 · 눌러 볼 순서 3~5개(누르면 무엇이 바뀌어야 하나 · 어느 요구 ID 인가) · 안 열릴 때 확인 순서. 마지막 줄 `다음 입력(서버): <실행 명령>` + `그다음(오케): (기능 지적 「<어디> <어떻게>」 · 다 되면 「다 끝」)`.
- **얇은 결과 시연 (11:50 목표)** — 오케 자체 점검이 통과해 첫 관통 결과가 서면 **디자인을 다듬기 전에** 곧바로 `docs/FEEDBACK.md` 첫판(0~2절 — 실제 데이터로 먼저 돌린 성공 기준 숫자와 요구별 상태)과 피드백 브리핑을 내고 「피드백 DM 시작하자」를 권한다(`M4-피드백.md`). 이유: 실무자의 의도 갱신을 일찍 받기 위해서다 — F1 은 핵심 정정이 첫 실물 화면을 본 뒤(마감 12분 전)에야 와서 반영이 마감 뒤였다. 아래 기능 검수·「다 끝」·디자인 검토는 이 DM 회신을 기다리는 동안 병렬로 이어간다.
- **기능 검수(사람 단계)**: 사용자가 Browser 로 직접 눌러 보며 지적하면 고친다(버그·틀린 숫자 = 고침 · 새 요구 = 웨이터의 No, 받을지는 사용자).
- **「다 끝」**(기능 확인을 마친 사용자가 친다) — 먼저 오케가 `guides/DESIGN.md` 기준으로 스스로 점검·수정한 뒤 **디자인 검토(사람 단계)**: 오케스트레이터가 스크린샷 경로 + 「디자인 시스템을 어디에 썼나」(토큰·컴포넌트별) + 화면 위→아래 설명을 내고, 사용자가 Browser 로 보며 「`<어디>` `<어떻게>`」로 지적하면 고친다. 오케스트레이터가 혼자 고치고 혼자 승인하지 않는다. 디자인 다듬기는 버리기 사다리의 세 번째 칸이다 — 12:35 신규 기능 금지 전에 끝나지 않으면 그 시점의 화면으로 간다.
- **「디자인 됐어」** — `build` 태그 커밋(PLAN 시간 앵커 실제 시각 채움) → 단계 전환 의식(M3 디브리핑 · M4 브리핑) → 피드백 DM 이 이미 진행 중이면 FEEDBACK 을 갱신해 다음 질문에서 **고친 결과를 다시 보여 준다**. 아직 DM 전이면 FEEDBACK 첫판 → 피드백 브리핑 → 마지막 줄 `다음 입력(오케): (궁금한 것 자유롭게 · 준비되면 「피드백 DM 시작하자」)`.
