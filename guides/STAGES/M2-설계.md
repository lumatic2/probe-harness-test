# M2 설계 — 「설계 DM 시작하자」 · 「설계 확정」 (오케스트레이터)

> `roles/오케.md` 「사용자 신호」가 여기를 가리킨다. 회신은 M1 과 같은 **DM 탭**(`roles/DM.md`)이 받는다 — 보낼 글 먼저, 요약은 `docs/interview/요약.md`(`M1-DM.md`). 마감선: 구현 시작 늦어도 11:15.

- **「설계 DM 시작하자」**(설계 브리핑을 두고 오케와 이야기한 뒤 사용자가 친다 — 의도를 붙이면 그것이 최우선) — **보낼 글을 가장 먼저**: `docs/interview/M2.md` 「질문 1」 = PLAN·ARCHITECTURE 를 실무자 말로(무엇이 나오나 · 사용자 흐름 · 경제적 효과(M1 기준선 대비 숫자) · 안 하는 것) + 실무자 판단이 필요한 데이터 처리 규칙·리서치 「실무자에게 확인할 것」 중 큰 것 2~3개, 기술 용어 없이. 질문 1 을 쓴 뒤 사용자에게 DM 탭에 `이제 M2 야 — docs/interview/M2.md 질문 1 을 보냈어` 를 치라고 안내한다(`다음 입력(DM): …`). 이후 회신은 DM 탭이 받아 질문·요약을 맡고, 오케는 `요약.md` 를 읽어 **설계에 필요한 만큼 PLAN·ARCHITECTURE 에 반영**한다(문제가 바뀌면 PROBLEM 도 취소선, 바뀐 줄만) · 관문은 **설계 확정 관문**(`guides/INTERVIEW.md`). 모듈 나눔에 실무자 동의가 나오면 스캐폴드(폴더 트리 · 시그니처만 있는 빈 파일 · 모듈별 계약 테스트 `tests/contract/` 빨강 확인 · 통합 테스트 1개 — 관통 테스트는 두지 않는다)를 만들고, 그 뒤 바뀐 설계는 스캐폴드까지 반영한다. 업무 갈림길은 실무자 질문으로, 기술 갈림길(저장·API·화면 수·라이브러리)은 오케가 정하고 `decision`.
- 관문 ㉠·자체 점검이 차면 **구현 직전 평가**를 서브에이전트로 띄운다(새 탭 없음): `roles/평가.md` 를 읽고 모드 1 을 따르는 맥락 없는 서브에이전트를 **병렬로 띄우고, 오케는 기다리는 동안 다음 일(남은 설계 DM 질문 · 브리프 초안)을 한 뒤 결과를 `wait` 로 받는다**고 명시한다. PLAN 위임 장부에 행을 연다. 평가가 마감선을 위협하면(구현 시작 11:15 임박) 버리기 사다리 두 번째 칸이다 — 건너뛰고 `decision`.
- **「설계 확정」**(M2 끝 — 설계 확정 관문과 평가 처분이 끝나 오케가 권하면 사용자가 판단해 친다.) — 관문을 다시 본다(미충족은 번호와 영향을 한 번 보이고, 그래도 확정이면 `decision`). `design` 태그 커밋(PLAN 시간 앵커 실제 시각 채움) → 단계 전환 의식(M2 디브리핑: 방향 한 줄 · 모듈과 나눈 이유 · 실무자가 동의한 것 · 안 하는 것 · 자를 순서 · 파일 경로 / M3 브리핑: 지금부터 무엇을 왜 · 사람이 할 일) → `brief` 스킬로 모듈 브리프 발행(발행마다 PLAN 위임 장부에 행을 연다 · `docs/brief/<모듈>.md` — 구현 탭이 이 한 장만 읽고 시작한다. 「요구에 없는 기능은 만들지 않는다」가 브리프에 고정이다) → **구현 탭은 3개 기준**(코어 · 화면 · 리포트 등 PLAN 모듈 2~4개 중 3개가 표준): 계산 코어가 먼저 필요하면 코어 탭이 먼저 시작하고, 화면·리포트 탭은 코어의 인터페이스(함수 시그니처 · 샘플 출력)를 **계약 파일** `docs/brief/계약-<모듈>.md` 로 받아 바로 병렬로 시작한다(브리프에 계약 파일 경로를 넣는다 — 계약 테스트는 오케 소유) → 구현 탭 안내를 모듈마다 한 줄씩: `새 탭 → codex → /model 가벼움 등급 · medium(경계 복잡하면 표준 등급) → 「docs/brief/<모듈>.md 읽고 그대로 해」 → 탭 이름 <모듈>`(동시 2 기본, 순서는 PLAN 7절). 브리프까지 상태가 다 파일에 있으므로 여기가 **승계 권장 지점**이다 — 마지막 줄 `다음 입력(<모듈>): docs/brief/<모듈>.md 읽고 그대로 해` + `그다음(오케): $succeed`. 실무자 동의 전에는 브리프를 발행하지 않는다.
