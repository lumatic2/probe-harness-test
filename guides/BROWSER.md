# BROWSER.md — 응시 환경 Browser 미리보기 연결법

> 출처: 2차 예선 사전준비 첨부 「사전 체험 및 응시환경 상세 가이드」 p3 「Browser에서 서비스 확인」(`docs/research/2026-10-26-2차예선-사전준비-첨부/_텍스트추출.txt` 원본은 대비 레포). 웹 결과물을 띄우기 전에 오케스트레이터가 읽는다.

## 순서
1. 서버는 **`0.0.0.0` 에 바인딩**한다. `localhost`/`127.0.0.1` 에만 붙이면 미리보기가 연결되지 않을 수 있다(안내문 명시). 10-30 사전체험에서 **포트 3000 고정**을 확인했다. 서버는 3000에서 띄우고 포트 충돌 시 다른 포트로 자동 이동하지 않는다.
2. 서버를 띄운 터미널 탭은 **닫지 않는다**(탭을 닫으면 프로세스도 죽을 수 있다). 서버 전용 탭 하나를 따로 두고 이름을 `서버` 로 한다. 그 탭에서 control+C 는 서버를 끈다(복사는 ⌘C — 맥 기준).
3. 사용자에게 **`http://localhost:3000/`** 링크를 준다. 사용자가 플랫폼 **Browser** 주소창에 복사·붙여넣어 연다(10-30 인사 화면·shadcn 대시보드 표시 성공). 하위 화면은 `http://localhost:3000/#/list`처럼 전체 링크로 준다. 확인하는 동안 서버 탭을 유지한다.
4. 「포트 N 에 아직 응답하는 서버가 없어요」는 서버 시작 전에도 뜬다. 서버가 준비되면 자동으로 다시 확인한다. 서버를 재시작했으면 원형 화살표를 다시 누른다.
5. 안 열리면 이 순서로 본다: 터미널의 오류·서버가 죽었나 → 실제 포트 → `0.0.0.0` 바인딩 → 경로.
6. 터미널 연결이 끊기면 터미널의 「다시 연결」, 안 되면 `+` 로 새 터미널. 미리보기가 멈추면 우측 상단 CPU/RAM 부터 본다 — 구현 탭·서버를 너무 많이 띄워 생긴 OOM 은 구제 대상이 아니다(FAQ). 쓸모없어진 탭·서버는 닫는다.
7. 서비스 확인은 플랫폼 안의 Browser 미리보기로만 한다 — 외부 브라우저 직접 접근은 감독 규칙을 따른다.

## 오케스트레이터가 사람에게 줄 안내(한 덩어리로)
- `서버` 탭에 칠 실행 명령 한 줄
- Browser에 붙여넣을 `http://localhost:3000/` 전체 링크
- 눌러 볼 순서 3~5개(무엇을 누르면 무엇이 바뀌어야 하나)
- 디자인 검토용 스크린샷 경로와 「디자인 시스템을 어디에 썼나」(`guides/STAGES/M3-구현.md` 「다 끝」)

## 미확인 — 사전 체험에서 확인
- 미리보기 주소(`…e2b.app`)가 외부에서도 열리는지 — 가이드는 「터널을 만들 필요 없다」「외부 브라우저 직접 접근 제한」이라고만 쓴다(보안 점검에서 「인증 없음」 위험을 어떻게 적을지)
- 서버 탭을 백그라운드로 돌릴 수 있는지(`&`·`nohup`) — 안 되면 탭 하나를 서버에 내준다
