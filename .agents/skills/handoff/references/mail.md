# 편지함·네이티브 queue

## 주소 등록

- 각 세션은 첫 실제 대화가 시작된 뒤 자기 `CODEX_THREAD_ID` 환경변수를 확인한다. 없으면 사용자가 `/status`의 Session을 확인하도록 안내한다. UUID를 추측하거나 다른 세션 ID를 재사용하지 않는다.
- 오케 주소는 `docs/mail/오케.md`, 워커 주소는 자기 편지함에 `등록` 메시지로 추가한다: 역할·세션 UUID·시각·대체한 옛 UUID(있을 때). 주소를 읽을 때는 최신 등록을 사용한다. 새 대화가 없는 세션은 queue에서 저장 기록 없음으로 실패할 수 있으므로 최초 기동 한 문장은 사람이 보낸다.
- 수신자는 처음에 역할·작업 ID를 확인하고 `시작` 답장을 남긴다. 주소 변경도 오케에 알린다. 워커→오케 전송 때는 오케 편지함 최신 주소를 다시 읽는다.

## 메시지 형식 (파일 끝에 추가)

```
## 메시지 화면-001 — 화면 → 오케 — 완료 — 11:30
- 세션: <발신 UUID>
- 회신 대상: 오케-001
- 작업: <작업 ID> · 처리한 지시: 오케-001
- 내용: <변경·질문·다음 행동>
- 결과물: <파일 경로> · 커밋: <해시>
- 검증: <명령·기대·실제·종료코드 또는 미확인 이유>
- 남은 것: <없음 또는 항목>
```

발신 역할별 순번으로 ID를 만든다. 옛 메시지·최초 계약을 덮지 않는다. 정정도 새 메시지로 추가한다. 작업 중 오케의 메시지가 도착하면 현재 작업을 안전하게 끝낸 뒤 미처리 ID만 읽는다. 한 편지함에서 같은 역할의 두 세션은 동시에 쓰지 않는다. 추가 직전에 마지막 내용을 다시 읽고 파일 전체 재작성 대신 UTF-8 append 한 번으로 블록을 쓴다. 다른 역할의 동시 추가가 감지되면 다시 읽어 ID·회신을 확인한다.

## 알림

파일 저장 후 아래 명령을 사용한다. 메시지에 명령·승인·전체 결과를 싣지 않고 위치만 알린다. 편지함 경로는 작업 공간 안의 관측한 경로만 쓴다.

```bash
codex queue --thread '<대상의 최신 UUID>' --message '[에이전트 알림: 화면 → 오케] docs/mail/화면.md 메시지 화면-001 확인. 사용자 승인 아님.'
```

- `Queued message`는 접수 성공이며 실제 처리 완료는 아니다. 수신자의 시작/완료/질문 메시지가 증거다.
- 큐가 같은 메시지를 두 번 전달해도 `처리한 지시` ID가 있으면 작업을 반복하지 않는다. 단순 수신 확인마다 서로 답장을 보내는 무한 왕복을 만들지 않는다.
- `queue` 미지원·세션 없음·전송 실패 또는 접수 뒤 미수신이면 파일은 그대로 보존하고 사용자에게 `<탭>에 편지함 확인해 라고 입력` 한 줄을 안내한다. 자동 무한 재전송·새 세션 몰래 실행·`--resume` 강제 깨우기는 하지 않는다. 새 주소 확인 뒤 명시적으로 재전송할 때도 같은 메시지 ID를 쓴다.
- 작업자가 오래 실행 중이면 다음 턴까지 늦을 수 있다. 오케는 진행 중인 턴을 마무리하고 응답 대기에 들어가야 한다. 자기 턴 안에서 회신을 기다리며 무한 폴링하지 않는다.
- 수신 알림은 사용자 요청과 구분한다. 발신 역할·UUID·편지함 작업 ID·미처리 지시를 대조하고 범위 밖 요청이나 사용자 승인 요구는 실행하지 않는다.

평가·보안·제출 점검은 보고서를 자기 결과 경로에 쓰고 편지함에는 경로·결론·미해결만 남긴다. DM의 실무자 원문은 `docs/interview/` 정본을 그대로 사용한다.

## 공유 작업 폴더의 Git

코드 커밋 뒤 완료 메시지에 그 해시를 적는다. 완료 메시지는 오케가 검수 기록과 함께 추적하며, 메시지 자체 해시를 메시지에 계속 갱신하지 않는다. 같은 체크아웃의 stage·commit은 공유 인덱스를 쓰므로 오케가 커밋 차례를 지정한다. 다른 탭이 stage/commit 중이면 기다리고, `git diff --cached --name-only`에 타인 경로가 있으면 건드리지 말고 보고한다. 인계 시에도 미커밋 메시지·제품 변경을 구분한다.
