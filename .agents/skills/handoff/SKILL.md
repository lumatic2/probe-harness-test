# handoff — 이어받기 정본 갱신

`docs/HANDOFF.md` 가 이어받기 지점의 유일한 정본이다. 다른 문서에 진행 상황을 따로 쓰지 않는다.

## 절차

1. 아래 형식으로 `docs/HANDOFF.md` 전체를 지금 시점 기준으로 다시 쓴다(없으면 만든다).
2. 쓰는 모든 파일·경로·숫자는 **지금 실제로 확인한 것만**. `ls`·`git log -1`·마지막 `docs/VERIFICATION.md` 줄로 확인한 뒤 적는다. 확인 못 한 것은 쓰지 않는다.
3. `AGENTS.md` 「목표·컨텍스트」가 대화 중 바뀌었는데 반영 안 됐으면 같이 고친다.
4. 스스로 판정: "새 세션이 AGENTS.md(오케면 `roles/오케.md` 도) + 이 파일만으로 다음 행동을 정확히 시작할 수 있나?" 부족하면 채운다.
5. 커밋: 마일스톤 전환이면 태그 커밋 `git commit -m "<태그>: <한 줄>"`(scaffold·define·design·build·feedback·final — 커밋 트리거 1), 아니면 `handoff:` 커밋(`handoff: <단계> — <한 줄>`).

## 형식

**읽는 사람 = 이 대화를 전혀 모르는 새 세션이나 다른 사람.** 대화 속 별명·약어를 쓰지 않고 파일 경로와 실무자 용어로 쓴다(채점: 의도 갱신 및 맥락 유지 「HANDOFF 로 승계 시연」 · 소통 「다른 사람·다른 세션이 자연스럽게 이어갈 수 있게」).

```
# HANDOFF — <시각> · 단계 <M0~M6> · 승계 사유 <있으면>
## 한눈에 (남이 읽어도 — 3~5줄)
- 누구의 무슨 문제: <진짜 문제 한 문장 — PROBLEM 0절>
- 성공 기준: <지표 · 기준선 → 목표> (PROBLEM 8절)
- 만드는 것 / 안 만드는 것: <한 줄씩> (PLAN 1절 · PROBLEM 10절)
## 지금 어디
- 단계: <현재 단계와 그 안의 위치> · 다음 사용자 신호: <「…」>
- 시간: 경과 <분> · 다음 앵커 <이름 HH:MM> 까지 <분> · 늦으면 자를 것: PLAN 7절 <첫 항목>
- 마지막 검증: <커맨드> → <PASS/FAIL/NOVERIFY> (<시각>)
- 마지막 커밋: <해시 앞 7자> <제목>
## 문서 지도 (지금 단계에서 읽을 순서 — 파일 · 무엇이 들어 있나)
1. <파일> — <한 줄>
## 끝난 것 (파일·기능 단위, 증거와 함께)
- <무엇> — <파일 또는 테스트 이름>
## 실무자와 합의된 것 · 열린 DM
- 합의: <무엇 — [답변N]> · 열린 DM: docs/interview/M<n>.md 질문 <N> (답 대기 여부)
## 굵은 결정 (최근 5개 — DECISIONS ID · 채택/기각 한 줄)
- <ID> <결정> — <이유>
## 다음 할 일 (첫 행동을 구체적으로)
1. <바로 실행할 수 있는 한 줄>
- 구현 세션별 상태(브리프 경로·진행·막힘): <세션> — <브리프 경로> · <진행> · <막힘>
## 지금 열려 있는 결정·막힌 것
- <무엇이 왜 막혔나 / 사용자에게 물을 것>
## 하지 말 것
- <신규 기능 금지 여부 · 건드리면 안 되는 흐름 · 공유 파일 소유 · 실무자가 거절한 것>
## 알려진 깨지는 지점 → docs/QNA.md 약점 지도 참조 (새로 생긴 것만 여기 한 줄)
## 이어받기 기록 (이어받은 세션이 채운다)
- <시각> · 이전 세션 사유 · 새 세션의 첫 3줄이 이 문서와 맞았나 · 모자랐던 것과 채운 것
```

## 새 세션 전환일 때 추가로

- 전환 이유(같은 실패 반복·지연·compact 2회째 중 무엇)를 HANDOFF 맨 위 한 줄과 DECISIONS 에 남긴다.
- 새 세션 첫 프롬프트는 `succeed` 스킬이 출력한 승계 프롬프트(정본 `guides/KICKOFF.md` 「승계」). 새 세션이 요약한 3줄이 HANDOFF 와 맞는지 사용자가 확인한다.
