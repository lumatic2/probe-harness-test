# PROMPTS.md — 위임 규약 (③ 스캐폴딩에 들어갈 때 읽는다)

> 모든 위임은 **완료 조건 + 보존할 제약 + 검증 방법**을 갖춘다. 「알아서 잘 만들어줘」는 없다.

## 위임 3줄 틀 (Cofa 공식 사이트의 좋은 프롬프트 기준: 원인·범위 먼저 → 보존할 제약 → 테스트와 결과 확인)

```
<무엇을> 해줘. 원인·범위: <왜 필요한가, 어디까지만 손대나>
- 지킬 것: <바꾸면 안 되는 동작·파일·인터페이스, 결정론 코어 규칙>
- 완료: <pass/fail 문장> — `./verify.sh "<커맨드>"` 통과하면 완료, 실패하면 고쳐서 같은 커맨드로 재통과
```

나쁜 위임(공식 사이트 예시): 범위 없는 위임 · 제약 없는 변경 허용 · 테스트 없이 완료 수용.

## 운용 규칙

1. **완료 보고를 그대로 믿지 않는다** — `verify` 스킬로 직접 확인한 뒤 다음으로 간다.
2. **작게 나눠 위임한다** — 한 위임 = 한 응집 변경. 끝나면 커밋(제목=무엇, 본문 한 줄=왜). 커밋 타임라인이 채점 데이터다.
3. **막히면 생각을 프롬프트로 꺼낸다** — 가설·시도·결과를 대화에 남긴다. 도구를 바꿀 땐 이유 한 줄.
4. **자원을 아낀다** — 필요한 파일만 읽히고, 큰 데이터·로그를 대화에 붙이지 않는다.
5. **시크릿 위생** — 키는 `.env` 에만(+`.env.example` 에 이름).

## 병렬 · 교차검증 (Codex 기준)

- 기본 = 메인 세션 하나. 독립 조사·모의채점·교차검증은 **맥락 없는 새 서브에이전트**로 돌린다(프롬프트에 산출물 경로+기준만, 제작 의도는 뺀다).
- 교차검증 용도는 문제 확정 직후와 제출 직전 코드. 결과는 전면 수용 금지 — 지적마다 검산하고 수용/기각을 `decision` 으로.
- 시간·진행 점검은 오케스트레이터의 단계 전환 의식이 한다(AGENTS.md 「세션 운용」).
- **긴 작업은 예상 소요를 먼저 말한다** — 사용자가 그 시간에 결과물을 읽고 이해할 수 있게(리허설: 최장 턴 16.8분이 전부 대기였다).

## 타이밍 (흐름에 맡기지 않는다)

| 행위 | 시점 |
|---|---|
| 커밋 | 응집 변경 1개마다 + 결정 기록마다 |
| HANDOFF | 단계 전환마다 + 새 세션 전환 직전 (`handoff`) |
| 리서치 | 문제 확정 직후 1회 + 막힐 때 (`RESEARCH.md`) |
| 모의채점 | 문제 확정 직후 · v0 직후 · 제출 전 (`JUDGE.md` 3회) |
| 예상 문제 공부 | M5 `final` 뒤 (`evaluate` 모드 2) |
| 검증 | 수정마다 (`verify`) |
| 약점 기록 | 보이는 즉시 `docs/QNA.md` |

## 루프

- 검증 가능한 종료 조건이 문장으로 없으면 루프 금지. 반복 상한(예: 6회) + 2회 연속 무개선이면 중단.
- 만든 세션이 스스로 채점하지 않는다(`JUDGE.md`).

## E2E 우선

- 비포장이어도 끝-끝이 먼저다. 입력→처리→결과가 한 번 관통한 뒤 다듬는다.
- 테스트는 실제 준 데이터 기반으로. 화면은 `starter/shell/smoke.mjs` 로 스크립트 확인, 수동 확인은 마지막 1회.
- starter 고르기: 화면형 → 기본 `bash starter/shadcn/make.sh`(shadcn 앱, 10분 상한) · npm 이 막히면 예비 `starter/shell/`(`guides/DESIGN.md` 맨 위)·(serve·index.html·위젯 13종·페이지 6종·csv·smoke, SK 토큰은 `vendor/skhynix/design.css` 한 곳) / 데이터형 → `starter/data/`(근거 행 표 처리). 안 쓰는 쪽은 폴더째 삭제. 라이브러리는 `guides/REFERENCES.md`.
- 과제 데이터로 바꾸기: 화면은 `starter/domains/<이름>/domain.json` 설정과 `sample.json` 만 바꿔 띄운다(화면 코드 수정 금지) — 순서 `starter/DOMAIN.md`.
