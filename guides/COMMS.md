# COMMS.md — 실무자 교신 규약 (한 파일 루프 · 화면 묘사)

> 사람이 두 창 사이에서 복붙 중계하므로, 보낼 원문과 받은 회신이 **한 파일에 순번으로** 쌓여야 중복 발송·구버전 전달 사고가 안 난다.
> (실측 사고: 같은 메시지 3회 중복 전송, 갱신 전 화면 설명 2회 재전송. 실무자는 텍스트만 본다 — 이미지·링크를 열 수 없다고 가정한다.)

## 한 파일 루프 (docs/interview/M<n>.md)

- 양식은 `docs/interview/TEMPLATE.md`. 보낼 원문은 세션 응답이 아니라 이 파일에 쓴다 — 사용자가 복사하는 단일 위치가 정본이다.
- **순번 규약**: 보낼 것은 `## 질문 N`, 받은 것은 `## 답변 N`, 그 뒤에 `- 반영:` 한 줄.
- **마일스톤마다 새 파일**: M1 발굴 · M2 설계 확정 · M4 피드백(마지막 답변이 수용 확인 — M5 DM 없음). 파일이 길어지면 읽기 비용과 오독이 늘기 때문에 길이를 이렇게 끊는다.
- **발송 전 직전 회신 재독 의무**: 새 「질문 N」을 쓰기 전에 직전 「답변」을 다시 읽고 ① 이미 답 받은 질문을 또 묻지 않는지 ② 회신의 정정·요구가 반영됐는지 확인한다.
- **회신 원문 보존**: 사용자가 붙인 그대로 둔다. 요약·해석은 `요약.md`(오케가 PROBLEM.md 로 옮긴다)에 하고, 여기는 마지막 수용 확인 때 「합의한 문장 그대로」를 대조할 근거다.
- 회신은 **DM 탭**(`roles/DM.md`)이 받는다. 한 턴에 ① 「답변 N」 기록 ② 「질문 N+1」 작성 + `docs/interview/보낼글.txt` 덮어쓰기(**가장 먼저** — 사용자가 턴이 끝나길 기다리지 않고 보낸다) ③ 답변 분해는 `docs/interview/요약.md` 에 바뀐 줄만(`[답변N]`) ④ 5줄 안으로 끝낸다. PROBLEM·STRATEGY 반영은 오케가 「문제 확정」 때 요약에서 한 번에 한다(`guides/INTERVIEW.md`).
- **보낼 글 전용 파일** `docs/interview/보낼글.txt`: 지금 보낼 글 하나만 담는다(매번 덮어쓴다). 사용자는 그 탭에서 ⌘A·⌘C 만 한다 — 긴 파일에서 범위를 드래그하지 않는다. 기록 정본은 `M<n>.md`.
- **질문 글 규칙**: 존댓말 메신저 구어체, 앞 답변의 말을 받아 시작, 상대 용어 그대로. 번호 목록은 허용, 굵은 글씨·소제목은 쓰지 않는다. 예: 「아까 월말에 몰린다고 하신 부분이 마음에 걸려서요, 다음과 같은 사항이 궁금해요. 1. ~ 2. ~」
- **사용자의 커트·수정**: 사용자가 초안을 고치거나 빼고 보냈다고 한 줄 알리면 에이전트가 `docs/DECISIONS.md` 에 기록한다. 사용자에게 문서 작성을 시키지 않는다.

## 화면 묘사 규약 (이미지 없음)

- **텍스트로만 보낸다**: 실무자는 이미지·링크를 열 수 없다. 화면은 캡처가 아니라 묘사 문구로 쓴다 — 형식은 `guides/INTERVIEW.md` ③ 중간 검증(첫 화면 위→아래 실제 값 · 누르는 순서대로 바뀌는 것 · 내려받는 결과물 원문 · 묘사한 부분을 짚는 질문).
- **시점마다 새로 쓴다**: 질문 순번마다 묘사를 처음부터 다시 쓴다. 옛 묘사의 일부만 고쳐 재사용하지 않는다 — 코드는 고쳐졌는데 묘사만 낡아 실무자에게 옛 화면을 설명하는 사고의 원인이다.
- **발송 전 전수검사**: 묘사를 인터뷰 파일 원문에 붙이기 전, 묘사의 주장(건수·금액·문구)을 실행 결과와 대조하는 체크를 1회 돌린다 — 항목은 "이번에 고쳤다고 말한 것 전부".
- 묘사는 발송 직전 1회 — 수정 중간마다 쓰지 않는다 (화면을 띄워 확인하는 왕복이 검증 루프 최대 시간 소모원이었다).
