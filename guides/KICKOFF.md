# guides/KICKOFF.md — 시작 순서와 세션 기동

> 사람이 외워서 치는 것은 아래 ⓪~② 와 역할 탭의 한 줄뿐이다. 긴 프롬프트를 붙여 넣거나 빈칸을 채우지 않는다 — 다음 할 일은 오케스트레이터가 매 응답 끝 `다음 입력:` 줄로 알려 준다(AGENTS.md 「사용자 신호」).
> 시험장 처음 상태: 웹 IDE 터미널은 `~/workspace $` 셸, 탐색기에 과제 README 와 폴더. Codex 는 꺼져 있고 우리 파일은 없다. 반입은 공개 레포 clone 뿐(개인 PC 업로드 불가).
> 재시작은 필요 없다 — 세팅이 끝나면 같은 Codex 세션이 그대로 오케스트레이터가 된다.

## ⓪ Codex 켜기 (터미널 셸)

```
codex
```

신뢰 확인이 나오면 작업 폴더(`~/workspace`)인지 보고 승인. **Codex 업데이트 권유가 떠도 업데이트하지 않는다**(건너뛰기 — 10-29 운영 메일: 버전 업데이트 금지, 제공 버전 그대로). 이어서 차례대로:

1. `/permissions` → **Full Access** — 최초 1회만. 한 번 바꾸면 이후 탭에도 이어진다.
2. `/model` → Sol 6.1 → effort **xhigh** — 끝까지 xhigh 로 간다. Max·Ultra 로 올리지 않는다(실측: 턴만 길어지고 질 이득 없음. Ultra 는 요청마다 다중 에이전트를 띄운다 — 서브에이전트는 각 세션이 필요할 때 직접 쓴다).
3. `/statusline` → 아래 여섯 개를 이 순서로 켜고 나머지는 끈다. 이어서 「Use theme colors」 를 켠다(한 번 고르면 `config.toml` 에 저장돼 이후 새 탭에도 같다).
   - `model-with-reasoning`(모델·effort) · `current-dir`(위치) · `permissions`(권한) · `context-used`(컨텍스트 사용량) · `five-hour-limit`(5시간 한도) · `weekly-limit`(주간 한도)
   이어서 `/status` 로 권한·모델을 눈으로 확인.
4. 터미널 탭을 더블클릭해 이름을 **`오케`** 로 바꾼다 — 탭이 늘어나기 전에.

새 탭은 `codex` → **매번 `/model`** 로 아래 표의 모델·effort 를 고르고 상태줄로 확인한다. 새 탭은 직전 탭의 `/model` 선택을 물려받으므로 건너뛰지 않는다. 권한은 다시 바꾸지 않는다. 그래도 승인 창이 뜨면 내가 눌러야 진행된다. 승인 창이 떠 있을 때는 회신을 붙여 넣지 않는다 — 붙여 넣은 글의 숫자가 선택지로 읽히고 회신은 사라진다. 승인 창을 먼저 처리하고 입력 칸이 보일 때 붙인다.

## ① 세팅 (외워서 친다 — 과제는 아직 읽지 않는다)

```
GitHub 의 lumatic2/probe-harness 레포를 이 폴더에 클론하고 README 대로 세팅해줘
```

Codex 가 레포를 찾아 작업 공간 안에 클론 → 클론 폴더 README 「세팅」 절 → `bash probe-harness/setup.sh` → AGENTS.md 를 읽고 setup.sh 가 출력한 **세팅 완료 보고 ①~④**(깐 것 · 환경 · 과제 파일 · 시간 앵커)를 말한다. setup.sh 는 과제 README·데이터를 덮지 않고, 과제가 준 AGENTS.md 는 우리 것 맨 끝 절에 붙이고, recon·복원 검증·`scaffold` 커밋까지 한다. 레포를 못 찾거나 clone 이 막히면 URL 을 손으로 넣지 않는다.

세팅이 도는 동안 사람은 과제 README 를 읽는다. 보고가 뜨면 ① 탐색기에서 `probe-harness/` 폴더가 **사라졌는지만** 본다(나머지는 보고가 확인했다) ② 에디터에 `docs/MEMO.md`·`docs/interview/보낼글.txt` 를 열어 둔다 — M1 내내 README·메모·보낼 글이 탭 전환 한 번 거리에 있게.

## ② 과제 브리핑

```
과제 브리핑해줘
```

시간 앵커는 setup.sh 가 이미 채웠다(화면 남은 시간이 다르면 「남은 시간 H:MM」을 덧붙인다). 오케스트레이터가 과제 README 를 스스로 찾아 과제 PROBLEM 첫판을 쓰고, 현장 사례 리서치 서브에이전트를 백그라운드로 띄운 뒤(새 탭 없음) 브리핑 6항목을 낸다(브리핑은 DM 전 첫판 — 대화하며 바뀐다). 브리핑을 읽는 동안 새 탭 하나에 `설명` 탭을 띄워 둔다(`/model` Sol 6.1 · medium → `roles/설명.md 읽고 그대로 해`) — 「지금 어디야?」 같은 내 이해용 질문은 그 탭에, 진행 지시는 `오케` 에. 이후 사람은 브리핑에 궁금한 것 자유 질문 → 「DM 시작하자」(그 턴에 첫 질문 `보낼글.txt` 가 먼저 나온다) → 실무자 회신 붙여넣기 → 「문제 확정」 순으로, `다음 입력:` 대로 친다.

## 역할 탭 (평가·리서치·보안·제출 점검)

기동 프롬프트를 붙여 넣지 않는다. 역할 문서 하나에 그 세션의 역할 · 읽을 파일 · 할 일 · 놓친 것 검증 · 결과 위치가 다 있다. 오케스트레이터가 모델·effort 와 함께 안내하면, 사람은 새 터미널 탭에서 `codex` → `/status` 확인 → 필요하면 `/model` 후 한 줄만 친다.

```
roles/<역할>.md 읽고 그대로 해
```

| 역할 문서 | 탭 이름 | 언제 | 모델 · effort |
|---|---|---|---|
| `roles/평가.md` (뒤에 「모드 1」·「모드 2」를 붙여 친다) | `평가` | 구현 직전(모드 1 — 설계 확정 관문이 찬 뒤) · M5(모드 2, 보안·제출 점검과 동시) — 대회 중 2번, 매번 새 탭 | Sol 6.1 · high |
| `roles/리서치.md` | `리서치` | M1 「문제 확정」 직후. 방향이 정해지면 pathfind | Sol 6.1 · high |
| `roles/보안.md` | `보안` | M5 1회(평가·제출 점검과 동시) — 끝나면 닫는다 | Sol 6.1 · high |
| `roles/제출점검.md` | `점검` | M5 1회(보안·평가와 동시) | Luna 6 · medium |
| `roles/설명.md` | `설명` | M1 시작 때 열어 끝까지 — 「지금 어디야?」「이 파일 뭐야?」 같은 내 이해용 질문은 여기에 | Sol 6.1 · medium |

탭 이름은 터미널 탭을 더블클릭해 바꾼다 — 오케스트레이터 탭은 `오케`, 구현 탭은 모듈 이름. 구현 탭은 고정 문서가 아니라 오케스트레이터가 모듈마다 만드는 브리프를 읽는다(Luna 6 · medium, 경계 복잡하면 Sol 6.1 · medium). 재지시는 그 브리프 맨 아래 「재지시」 절 — 사람은 그 탭에 「브리프 맨 아래 재지시 읽고 해」.

```
docs/brief/<모듈>.md 읽고 그대로 해
```

## 승계 (오케스트레이터 열화 때 — `succeed` 스킬이 출력한 프롬프트를 새 탭에 붙인다)

```
AGENTS.md 와 docs/HANDOFF.md 를 읽어라 — HANDOFF 가 이어받기 정본이다. 이어서 HANDOFF 「문서 지도」의 파일을 순서대로 읽어라. 너는 오케스트레이터를 이어받는다(사유: <…>). 지금 <date 로 읽은 지금>, 확정 목표 12:55.
① 지금 상황 3줄 ② 다음 할 일 1개 ③ 다음 앵커까지 남은 시간 — 말한 뒤 내 확인을 받고 진행하라.
```

워커 승계는 `succeed` 워커 모드가 출력한다: 「AGENTS.md · docs/brief/<모듈>.md · src/<모듈>/HANDOFF.md 를 읽고 이어가라」.

## 컨텍스트 관리

- compact 는 상태가 전부 파일에 들어간 순간에만(권장 지점은 AGENTS.md 「세션 운용」). 직후에는 AGENTS.md + HANDOFF + 현 단계 guide 를 다시 읽는다.
- 승계 기준은 AGENTS.md 「세션 운용」. 코파톤(225분)에서 compact 반복으로 후반 요청 1건이 15분까지 늘었다 — 180분에서는 더 빨리 승계한다.
