# M2 방향 — 「리서치 끝」·「pathfind 끝」·「평가 끝」(M2 몫) · 「그 방향으로 가자」 (오케스트레이터)

> `AGENTS.md` 「사용자 신호」가 여기를 가리킨다. M2 의 기다리는 일(리서치 · pathfind · 구현 직전 평가)은 새 탭이 아니라 **오케가 띄운 서브에이전트**다. 서브에이전트 결과는 오케가 `wait` 로 받으므로 사용자가 끝 신호를 칠 일은 보통 없다 — 사용자가 「리서치 끝」 등을 쳐도(서브가 이미 파일을 남겼으면) 아래 처리를 그대로 한다. M5 의 「보안 끝」·「평가 끝」(모드 2)·「점검 끝」은 `M5-제출.md`.

- **「평가 끝」·「리서치 끝」·「pathfind 끝」**(서브에이전트 결과를 받았을 때 — PLAN 위임 장부의 그 행에 실제 소요·결과를 채운다) — 터미널이 아니라 **결과 문서를 직접 연다**(평가 `docs/judge/` 의 가장 새 파일 · 리서치 `docs/research/요약.md` · pathfind `docs/research/pathfind/`). 문서가 없거나 양식 절이 비었으면 고치지 말고 그 서브에이전트에 다시 시킨다. 리서치: 결론 · 갈림길 · PROBLEM 과 어긋나는 것 · 실무자에게 확인할 것(설계 DM 후보로 둔다)을 사용자에게 요약하고 방향 대화를 연다. pathfind(선택 단계): 연구노트 첫머리 표를 PLAN 5절에 옮겨 PLAN 을 마무리 → `docs/ARCHITECTURE.md` 첫판 → **설계 브리핑**(3줄 · 구조도 · 「왜 이렇게 나눴나」 — 사용자가 설명 못 할 구조는 단순화, 설계 DM 전 첫판이라 대화하며 바뀐다고 명시) → 마지막 줄 `다음 입력(오케): (설계에 궁금한 것 자유롭게 · 준비되면 「설계 DM 시작하자」)`. pathfind 를 건너뛰었으면(시간 부족 · 마감선 지킴) 그 사실을 `decision` 에 한 줄 남기고 PLAN 5절은 「건너뜀」 + 이유로 채운다. 평가(구현 직전 1회): 지적 ID 마다 PROBLEM·PLAN·ARCHITECTURE·`guides/RUBRIC.md` 와 대조해 정말 빠진 것인지 검산 → 수용(그 자리에서 고친다 — 설계가 바뀌면 스캐폴드까지) · 기각(이유) · 실무자 확인(다음 설계 DM 질문에 싣는다) — 처분을 `decision` 으로 한 줄씩, 전면 수용 금지. 처분이 끝나면 설계 확정 관문 ⑮ 를 보고 「설계 확정해도 됩니다」를 권한다.
- **「그 방향으로 가자」**(M2 앞부분 — 리서치 결론을 두고 오케와 대화한 뒤 사용자가 친다. 「그래, 그걸로 가자」처럼 방향을 고르는 말이면 이 신호다 — 오케는 고른 방향을 한 줄로 되말하며 시작한다) — 고른 방향과 버린 후보를 `decision` 으로 남기고(채택·기각 이유, 근거 `docs/research/…`) PROBLEM 성공 기준·MUST 와 어긋나는지 한 줄로 확인한다. 그다음 **pathfind 서브에이전트**(선택 단계 — 마감선이 빠듯하면 건너뛴다)를 띄운다: `.agents/skills/pathfind/SKILL.md` 를 읽고 `pathfind — <방향 한 줄>` 을 **병렬로 돌리고, 오케는 기다리는 동안 다음 일을 한다**고 명시한다. 산출은 연구노트 md 하나(`docs/research/pathfind/`, HTML 렌더 없음). pathfind 가 도는 동안 오케는 PLAN 1·3·6·7·8절(방향 · 분기 판정 3 · 모듈 후보 · 순서·자를 순서 · 검증 수단)을 채운다 — 2·4·9절은 리서치 동안 이미 썼고 5절은 pathfind 몫이다. 서브에이전트가 끝나면 위 pathfind 처리.
