> UI 코드를 쓰기 전에 읽는다. 산출물은 마케팅 페이지가 아니라 **실무자가 매일 여는 내부 운영 도구**다.
> **화면 출발점(사용자 결정 10-29)**: 기본 = `bash starter/shadcn/make.sh` 로 세우는 shadcn 앱(페이지 6개 + 도메인 설정으로 켜는 3개(일정 격자 `#/schedule` · 문서 검토 `#/review` · AI 기능 `#/assist`) · 위젯 18종(W17 = AI 대화창, 헤더 버튼 옆 패널 · W18 = 녹음·전사) · SK 색 · 한국어, 약 1분). **npm 이 막히면** 예비 = `starter/shell/`(같은 페이지·위젯의 바닐라판, 설치 0분, 사용법 `starter/shell/README.md`). 사전 체험의 npm 확인 결과로 당일 아침에 정한다. 토큰 정본은 `vendor/skhynix/design.css` 하나 — 아래 「토큰」 블록은 규칙 설명용이고 앱 CSS 에 다시 정의하지 않는다(E1 의 선택자 충돌 원인).

**빠른 시작 — 앱용 파생 규칙**
1. 앱 주색 #ff6600(--skh-accent); YAML primary=#ffffff는 원본 IR 링크 관측이다. 캠페인 #ff8e20은 기본 버튼에서 제외한다.
2. 글꼴 = Pretendard 고정(사용자 결정 10-29), 키트 동봉(`vendor/fonts/PretendardVariable.woff2`, OFL-1.1) — 외부 폰트 요청 없음. 대체: "Malgun Gothic","Apple SD Gothic Neo",system-ui,sans-serif.
3. 반경 0px; 간격 4·8·12·16·24·32px; .skh-button--primary로 주 버튼을 만든다.
4. 표: .skh-table, 44px 행, 숫자 우측·단위 머리·미수집 —·표 안 가로 스크롤.
5. 차트: 기본 #ff6600(사용자 결정 10-29)과 회색; 필요할 때만 아래 범주형 6색. 라이트 모드만 쓴다(다크 없음).

   - shadcn 은 원본 컴포넌트 모양·상태 표현을 바꾸지 않는다 — 바꾸는 것은 색 토큰·데이터·라벨뿐(사용자 판정 10-29: 원본에 없는 장식 = slop). 기준 그림 `guides/img/shadcn-recipe-sk.png`
6. 개선은 중립색, 악화는 위험색; 방향과 개선/악화 글자를 함께 쓴다.
7. 금지: 로고/워드마크·외부 요청/폰트·무지개/3D 차트.
8. 데이터 화면 전체를 <main class="skh-dashboard">로 감싼다. 아래 필수 적용 조건을 지킨다.

> 키트 사본: `vendor/skhynix/{DESIGN.md,design.css,components.html}` (킷 기준 경로, 원본 변경 금지). `design.css` 를 `<link rel="stylesheet" href="vendor/skhynix/design.css">` 로 동봉하고 데이터 화면 전체를 `<main class="skh-dashboard">` 로 감싼다. 컴포넌트 예시는 `components.html`, 전체 규칙은 `vendor/skhynix/DESIGN.md`. 주색은 `#ff6600`(`--skh-accent`) — 해커톤 사이트색은 쓰지 않는다.

## 원칙

1. **정보 위계가 디자인이다** — 요약 숫자(3~4개) → 오늘의 큐(행동 대상) → 상세·근거 순. 가장 중요한 것이 가장 크고 가장 위에.
2. **상위 N 시각 분리** — 목록이 있으면 "먼저 볼 것"이 테두리·배경으로 구분돼야 한다. 전부 같은 무게면 아무것도 안 중요한 것.
3. **색은 의미다** — 상태색은 의미에 고정하고(아래 토큰), 장식으로 쓰지 않는다. 색만으로 의미를 전달하지 않는다 — 반드시 텍스트 라벨 병기(색약·흑백 인쇄 대응).
4. **숫자는 정렬한다** — 금액·건수는 `font-variant-numeric: tabular-nums` + 우측 정렬. 천 단위 콤마.
5. **의존성 0** — 외부 CDN·외부 웹폰트 금지, 동봉 vendor(`vendor/skhynix/design.css`·`vendor/fonts/`) 허용(오프라인 샌드박스에서 죽는 지점은 외부 요청이다). **폰트 = Pretendard 고정(사용자 결정 10-29), 키트 동봉.**

## 스케일 (컴팩트 — 운영 도구 밀도)

| 용도 | 크기/무게 |
|---|---|
| 화면 제목 h1 | 20px / 700 — 화면당 1개 |
| 섹션 제목 h2 | 16px / 700 |
| 본문·테이블 | 15px / 400 |
| 캡션·메타 | 13px / 400, `--ink-muted` |
| 핵심 지표 숫자 | 24~28px / 700, tabular-nums |

- 여백 단위 4px 배수(8·12·16·24). 카드 패딩 16px, 섹션 간 24px.
- 테이블: 헤더는 13px 굵게 `--ink-muted`, 행 구분은 `--line` 1px, 행 hover 배경 `--bg`. 셀 패딩 8px 12px.
- 배지(상태 라벨): 12~13px, 상태색 배경/글자 쌍, border-radius 0(키트 「반경 0px」), 패딩 2px 8px.
- 버튼: 주 행동 1개만 `--skh-accent` 채움, 나머지는 테두리 버튼. radius 0 — 키트 `.skh-button` 을 쓴다.

## 형태 규율 — AI 상투형 회피

생성형 도구가 기본으로 뱉는 형상들이 있다. 그대로 내면 다른 참가자들과 같은 화면이 된다:

- **둥근 카드 + 왼쪽 액센트 레일 금지** — AI 대시보드의 대표 상투형. 강조는 순위 숫자·굵은 상단 룰·배경 톤으로.
- **radius는 0(키트), 손 CSS 도 4px 이하** — `rounded-lg`(8px+) 남발이 상투형의 절반이다. 운영 도구는 각져도 된다.
- **KPI 낱개 박스 나열 금지** — 지표 4개를 박스 4개에 담지 않는다. **한 면 위에 수직 헤어라인으로 구분한 스탯 바**가 같은 정보를 더 밀도 있게 전한다.
- **박스 안 박스 금지** — 테두리는 면이 의미를 바꿀 때만. 구획이 필요하면 먼저 여백과 제목으로, 그다음이 헤어라인, 테두리 박스는 마지막 수단.
- **목록의 기본형은 카드 그리드가 아니라 테이블(행)** — 스캔·비교가 일인 화면에서 카드는 밀도를 죽인다. 카드는 항목이 5개 이하이고 각 항목에 여러 줄 서사가 붙을 때만.

## 인터랙션·차트 규율

판단 기준 하나: **실무자의 클릭·판단을 줄이는가.** 보여주기 위한 움직임은 전부 감점 신호다.

**넣을 값어치 있는 것 (선택지)**
- **접힘 섹션** — 보조 정보(제외된 건·상세 로그)는 네이티브 `<details><summary>`로. JS 아코디언 구현 금지 — 네이티브가 접근성·포커스 공짜.
- **정렬·필터 토글** — 큐가 20건 넘으면 유형별 필터가 클릭을 줄인다. 토글 상태는 URL이나 화면에 보이게.
- **행동 버튼 + 즉답 피드백** — "복사" 누르면 버튼 라벨이 "복사됨 ✓"으로 1~2초 — 제어가 결과를 말한다. 토스트 라이브러리 불요.
- **행 hover 하이라이트 · 행 클릭 상세** — 상세는 인라인 펼침(details)이 모달보다 낫다(맥락 유지).
- **차트** — 아래 규율로, 필요할 때만. **숫자가 3~4개면 차트가 아니라 스탯 바가 이긴다.**

**차트 규율 (쓸 때)**
- 의존성 0 — 손 SVG 또는 div 막대. Chart.js 등 CDN 금지(오프라인 + 의존성 원칙).
- 허용: 막대·선/면·100% 누적 막대·히트맵·진척 막대·퍼널·간트 간이판(셸 위젯 W1~W18). 금지: 3D·도넛·파이·그라데이션 채움·카운트업. 색은 토큰만 — 기본 회색, **강조는 딱 하나**(`--skh-data-accent`, 문제의 막대만 상태색). 히트맵은 sequential 단색 농도 + 칸 수치.
- W17 AI 대화창: 말풍선은 AI = `muted` 배경, 사용자 = 기본(검정) — 원본 톤 그대로, 장식·아바타·글자 효과 없음. 응답 옆에 「AI 응답」/「모의 응답」 배지를 항상 둔다(어느 쪽인지 숨기지 않는다). 질문 칩·입력칸에 설명 캡션·지시형 문구를 붙이지 않는다.
- 축·단위 라벨 필수, 숫자는 tabular-nums. 범례가 필요하면 차트가 너무 복잡한 것.

**금지 (슬롭 신호 — 운영 도구에서 즉사)**
- 마키·캐러셀·자동 슬라이드 (읽는 속도를 도구가 정하는 것)
- 3D·파티클·틸트·패럴랙스 (판단에 기여 0, 성능 비용만)
- 스크롤 트리거 리빌 · 숫자 카운트업 애니메이션 (두 번째 볼 때부터 대기 시간)
- hover 시 카드 떠오름(translateY+그림자 확대) — AI 상투형 대표
- 스켈레톤 쉬머 남발 (로컬 데이터엔 로딩이 없다)

**모션 한도**: 상태 전환(hover·접힘)만 100~150ms ease-out. `prefers-reduced-motion` 존중. 그 외 움직임 0.

판단 원칙: **설치 시간 + 오프라인 리스크 + 슬롭 수렴** 3개를 넘는 이득이 없으면 바닐라. "익숙해서"는 이유가 아니다 — 익숙함은 토큰 CSS 쪽이 더 크다(복붙 시작).

## 운용

- E2E v0 단계에선 `starter/shell/` 을 그대로 쓰고 필요한 페이지·위젯만 남긴다 — 디자인 고민 0분으로 "거칠지 않은 기본"을 확보하고, 폴리싱은 마지막(PROMPTS.md E2E 우선).
- 과제 도메인에 맞는 더 풍부한 디자인 언어가 필요하면 도구 사다리 ②로 `npx getdesign@latest add <이름>` (getdesign.md 카탈로그 — 내부 도구 장르 최적합은 airtable로 사전 판정, 사본을 오프라인 지참). 추가 시 이유 한 줄을 `docs/DECISIONS.md`에.
- 최종 전 사람 눈 확인 1회: "처음 30초에 오늘 뭘 할지 보이는가" — 안 보이면 스타일이 아니라 **정보 배치**를 다시 짠다.
