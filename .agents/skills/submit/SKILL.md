# submit — 제출 점검 (M5, 10분 상한)

제출 미리보기에는 일부 파일만 보이고 확정 뒤엔 고칠 수 없다. 클린 재현·증거 점검은 M3 오케 자체 점검에서 이미 한 번 돌았다 — 여기서는 최종 커밋 직전 상태로 다시 확인한다. 아래를 순서대로, 각 항목에 통과/지적.

1. **필수 파일명**: 과제 README·과제 안내가 지정한 제출 파일명·경로가 정확히 있나(`ls`). 지정이 없으면 `README.md` 루트.
2. **README 증거**: `python3 tools/evidence_check.py README.md` → 0. 모듈 README 도: `ls src/*/README.md` 가 루트 「구조와 설계 근거」 표의 모듈과 1:1 이고, 각 파일의 검증 명령을 실제로 한 번 돌려 통과하며, 언급한 파일·함수가 실제로 있다(`evidence_check` 는 「된다」 표가 없는 모듈 README 에 exit 2 — 그건 정상). 「된다」 표의 칸마다 테스트 이름·`파일:줄`·명령이 있고 언급한 파일이 전부 존재. 「안 된다·남은 한계」 절이 있나(선택한 판단과 근거·검증 결과·남은 한계 — 공식이 요구한 4요소).
2-1. **README 「AI 활용 기록」 대조**: 루트 README 에 이 절이 있고(`evidence_check` 가 절 존재를 검사), 탭 수 · 위임 수 · 재작업 수 · 앵커 차이가 `docs/PLAN.md` 「위임 장부」·「시간 앵커」 표를 직접 센 값과 같다. 다르면 지적(고침은 오케스트레이터).
3. **교체 지점 표**: 환경변수·외부 서비스·AI 모델 교체 지점이 README 표에 빠짐없이(코파톤 실측: 변수 하나 누락으로 부분 충족). 환경 변수는 `python3 tools/env_check.py` → 0(코드가 읽는 변수 중 README 「환경 변수」 표에 없는 것 0 — 「남음」은 낡은 행이니 지운다).
4. **낡은 문서 청소**: 빈 템플릿(`docs/brief/` 미사용·`starter/` 안 쓴 갈래·`docs/interview/TEMPLATE.md`)·스캐폴드 잔재·중복 문서 삭제 목록을 만든다(삭제는 오케스트레이터).
5. **클린 재현**: 새 임시 폴더에 `git archive HEAD | tar -x -C <임시>` 후 README 절차 그대로 설치·검증·실행. 결과를 `docs/VERIFICATION.md` 에 시각과 함께.
6. **전체 테스트**: `./verify.sh "<전체 테스트 명령>"` PASS.
7. **저장 상태·커밋**: `git status --porcelain` 비어 있나. 사용자는 `docs/MEMO.md` 말고는 에디터로 고치지 않으므로 디스크 = 제출물이다 — 사용자에게 확인을 요청하지 않는다.
8. **금지 패턴**: `python3 tools/security_check.py` 막는 것 0(`.env` 추적 · 키 문자열) + 개인정보.

출력: 통과/지적 목록 → 오케스트레이터가 지적을 처리하고 `final` 커밋. 그다음 평가 탭(모드 2)이 예상 문제를 쓴다.
