# M1 확정 — 「문제 확정」 신호를 받았을 때 (오케스트레이터)

> `roles/오케.md` 「사용자 신호」가 여기를 가리킨다. 마감선: 문제 확정 10:40(넘기면 아래 마지막 줄의 버리기 규칙)..

- **「문제 확정」**(M1 끝 — 오케가 「문제 확정 관문」이 찼다고 권하면 사용자가 판단해 친다) — `python3 tools/problem_check.py` + 관문(`guides/INTERVIEW.md` — **숨은 사실 점검표** 포함)을 다시 본다. 미충족이 있으면 번호와 영향을 한 번 보이고, 사용자가 그래도 「문제 확정」이면 미충족을 `decision` 으로 남기고 M4 피드백 질문으로 넘긴다. **먼저 `docs/interview/요약.md`(DM 탭이 쌓은 규칙 · 숫자 · 합의 · 미확인 · 숨은 사실 점검표 · 관문 상태)를 읽고 PROBLEM 해당 절에 `[답변N]` 으로 한 번에 반영한다**(바뀐 줄은 취소선, 통째 재작성 금지) — DM 탭은 PROBLEM·STRATEGY 를 고치지 않았다. 숨은 사실 점검표(단위 · 중복 · 시간대 · 제외 대상 · 분류 기준 · 빈 값 의미 · AI 사용/외부 전송 · 개인정보)에 「아직」이 남았으면 그 줄을 먼저 보이고, 보류·미분류·제외 비율이 10% 를 넘는 항목이 있으면 함께 보인다(관문 번호 체계와 별개의 추가 체크다).
- PROBLEM 확정 시각 → `define` 태그 커밋(PLAN 시간 앵커 실제 시각 채움) → 단계 전환 의식(M1 디브리핑: 진짜 문제 한 문장 · 성공 기준 · MUST · 하지 않을 것 · 남긴 미확인 · 파일 경로 / M2 브리핑: 지금부터 무엇을 왜 · 사람이 할 일).
- **같은 턴에 리서치를 서브에이전트로 띄운다**(새 탭 없음): 디브리핑을 먼저 낸 뒤 `roles/리서치.md` 「첫 일」대로 갈래 서브에이전트를 **병렬로 띄우고, 모두 기다린 뒤 요약**하라고 명시한다(서브에이전트는 자동으로 안 뜬다 — 리서치 문서 2절). 갈래마다 PLAN 위임 장부에 행을 연다. 기다리는 동안 오케는 방향과 무관한 `docs/PLAN.md` 2·4·9절(요구 추적 표 · 데이터 처리 규칙 · 위험)을 쓴다. 갈래가 끝나는 대로 한 줄씩 사용자에게 알린다. 다 끝나면 `docs/research/요약.md` 를 읽고 결론 · 갈림길 · PROBLEM 과 어긋나는 것 · 실무자에게 확인할 것(설계 DM 후보)을 요약해 방향 대화를 연다. 갈림길 중 **업무**(무엇이 쓸 만한가 · 읽는 순서)는 사용자에게 고르게 하지 않고 설계 DM 질문으로 올리고, **기술**은 오케가 정해 `decision` 으로 남긴다. 마지막 줄 `다음 입력(오케): (리서치 요약을 읽고 가고 싶은 방향을 말하기 — 「그 방향으로 가자」)`.
- M2 일의 몫: 리서치 서브에이전트 = 딥 리서치·도메인 렌즈 → pathfind(선택) · 오케 = 방향 대화 · PLAN · ARCHITECTURE·스캐폴드 · 설계 DM · 평가 지적 검산 · 평가 서브에이전트 = 구현 직전 1회(모드 1). 오케스트레이터가 해법 후보를 먼저 내지 않는다.
- 문제 확정이 10:40 을 10분 넘기면 남은 미확인을 M4 실무자 피드백으로 미루자고 제안하고, `AGENTS.md` 「진행 단계」의 버리기 사다리를 첫 칸부터 시작한다.
