# 공통 — 세션 운용 · 새 탭 띄우기 · 판단 원칙 · 신호어 규칙 (모든 단계)

> `AGENTS.md` 의 「세션 운용」·「판단 원칙」·「사용자 신호」머리말이 여기를 가리킨다. 단계 전환 의식·위임 장부·승계·compact 의 전체 문장이다.

## 새 세션이 필요할 때 (탭 띄우기)

사용자는 새 터미널 탭에서 `codex` → **`/model` 로 그 탭의 모델·effort 를 매번 고른다**(새 탭은 직전 탭에서 고른 `/model` 을 물려받는다 — 설정 파일 하나, 리허설 E1 에서 승계 오케가 Luna 로 뜬 원인. 그래서 「같으면 건너뛰기」 없이 매 탭 고른다) → 상태줄(없으면 `/status`)에서 모델·effort 를 눈으로 확인 → 한 줄만 친다(권한은 최초 1회 `/permissions` → Full Access, 이후 탭에 이어진다): 고정 역할은 「`roles/<역할>.md` 읽고 그대로 해」, 구현은 「`docs/brief/<모듈>.md` 읽고 그대로 해」, 승계는 `succeed` 가 출력한 프롬프트 붙여넣기(정본 `guides/KICKOFF.md`). 오케스트레이터는 탭 안내 한 줄에 **`/model` 의 모델·effort → 칠 문장** 을 같이 쓴다(예: `/model` 가벼움 등급 · medium → 「`docs/brief/core.md` 읽고 그대로 해」 — 등급별 모델은 `guides/KICKOFF.md` 세션 편성 표). 그리고 **탭 이름**(`오케`·`DM`·`평가`·`보안`·`점검`·`설명`·모듈 이름 — 탭 더블클릭으로 바꾼다)까지 안내한다. 엉뚱한 탭에 치는 사고를 막는다. 토큰·비용은 관리자 표에 열로 보인다 — 새 탭은 구현·M5 점검처럼 오래 도는 일에만 연다.

## 다음 입력 줄

모든 응답의 마지막 줄은 `다음 입력(<탭 이름>): <사용자가 칠 말 한 줄>` — 사용자가 칠 말만 쓰고, 어느 탭에 칠지 탭 이름(`오케`·`DM`·`설명`·모듈 이름…)을 붙인다(에이전트 자신의 다음 할 일은 이 줄에 쓰지 않는다). 오케에 칠 말이 없고 다른 탭을 기다리는 동안이면 보고성 입력(「~시작했어」「~알려줘」)을 지어내지 않는다 — 다른 탭에 칠 말을 쓰고, 그 탭이 끝나면 오케에 옮길 말을 `그다음(오케): <모듈> 끝` 처럼 덧붙인다. 탭이 더 필요 없어지는 경계(M4 끝 구현 탭)에서는 응답에 「닫아도 되는 탭: …」 한 줄을 넣는다. DM 원문을 새로 쓴 응답의 `다음 입력:` 은 실무자 회신 붙여넣기다 — 사용자가 칠 것은 실무자 답 원문 그대로이지 「실무자 회신 붙여넣기」라는 글자가 아니다. 예: `다음 입력(오케): (DM 의 실무자 답을 그대로 붙여넣기)`.

## 신호어 + 의도, 자유 지시

신호어는 외우는 암호가 아니라 흐름의 표지다(문구가 달라도 뜻이 같으면 그 신호). 사용자가 「DM 시작하자, 단위부터 확인해」처럼 **의도를 덧붙이면** 오케는 그 의도를 최우선으로 따르고 `decision` 에 「제안: 사용자 → 채택」으로 남긴다(AI 제안의 채택·수정·거절 이유 기록). 사용자가 신호어 대신 **자유 지시**를 해도 흐름을 이어간다 — 그 지시를 한 대로 하고, 끝나면 지금 단계의 `다음 입력:` 으로 돌아온다(자유 지시 대화도 AI 네이티브 증거다 — 대화를 수집해 간다).

## 판단 원칙 — 실무 문제를 데이터로 확인하고, 동작하는 결과물로 푼다

- **README 를 먼저 믿고 실무자에게 확인한다**: 요구를 표로 옮기고, 빈 칸과 어긋난 칸만 실무자 DM 으로 묻는다(`docs/interview/M<n>.md`, `guides/INTERVIEW.md`). 질문 수 제한은 없다 — 문제 정의서가 찰 때까지.
- **문제 하나, MUST 먼저**: MUST 를 전부 닫기 전에 선택 항목을 시작하지 않는다.
- **결정론 코어**: 판정·계산·집계·필터는 규칙이 고정된 코드 + 테스트. AI 의 자리는 해석·초안·검토. 결과를 내는 AI 호출에는 고정 폴백. **제품 안 AI 호출**: 과제 README 「실행 환경」이 API 를 제공해도(`OPENAI_API_KEY`·`OPENAI_BASE_URL`) 제품에 AI 기능을 넣을지는 **실무자와 DM 으로 상의해 정한다**(숨은 사실 점검표 「AI 사용/외부 전송」 칸에 답변 번호로 연결 — 외부 전송 허용 여부 · 쓰고 싶은 자리 · 틀렸을 때 폴백). 쓰기로 하면 그 환경변수로 쓴다(키는 코드·커밋·로그 금지, README 환경 변수 표에 이름만) · 제공하지 않거나 안 쓰기로 하면 모의(결정론 폴백) — 개인 API 키는 어느 경우에도 금지, 제공 AI 는 Codex 뿐이다.
- **데이터가 크면 대화로 세지 않는다**: 구조(파일·열·행 수)만 보고 처리는 코드로. 결론마다 근거 `파일:행`. 같은 AI 에게 다시 검증시키는 것은 검증이 아니다 — 핵심 숫자는 구현과 별개로 원본에서 다시 센다(M4 「독립 재계산」).
- **데이터 먼저 의심**: 결측·중복·단위·ID·기간 경계를 코드로 점검(`starter/data/table.py profile`), 처리 규칙은 DECISIONS 에. 보류·미분류·제외가 10% 를 넘으면 실무자에게 묻는다.
- **세 가지 왜**: ① 데이터 원천·한계 ② 안 풀면 무엇이 비싼가 ③ 결과를 받은 사람이 다음에 무엇을 하나.
- **웨이터의 No**: 요구를 받아 적지 않는다. 데이터·제약과 안 맞으면 근거를 들어 다르게 제안한다. 요구에 없는 기능은 만들지 않는다.
- **작동하는 결과물이 먼저**: 입력→처리→결과가 한 번 관통한 뒤 다듬는다. 문서에만 있는 기능은 0점.
- **내가 설명 못 하는 구조는 만들지 않는다**: 새 구조는 그 자리에서 3줄 브리핑. 사용자가 서술형에서 직접 설명한다.
- **업무 결정 vs 기술 결정**: 업무 갈림길(무엇을 먼저 보나 · 무엇이 쓸 만한가 · 읽는 순서)은 실무자 DM 질문으로, 기술 갈림길(저장 · API · 화면 수 · 라이브러리)은 오케가 정하고 `decision`. 사용자에게 고르라고 내밀지 않는다.

## 세션 운용

- **단계 전환 때마다(5분 상한)**: ① 시간 보고(경과·잔여·다음 앵커) ② 감사 3문(드리프트 · 증거 없는 체크 · 순조로움 의심) ③ 채택·기각 대안을 `decision` 으로(+ 「병렬로 돌린 것 · 기다린 것 · 왜」 한 줄) ④ 그 경계의 평가·보안 호출(`AGENTS.md` 「세션 편성」 수명 열)을 했는지 적고, 생략이면 이유를 `decision` 으로 ⑤ 커밋 ⑥ **사용자에게 디브리핑·브리핑**(그 응답 안의 말로 — 따로 단계를 두지 않는다): 방금 끝난 단계에서 무엇을 했고 무엇이 정해졌나·산출물 경로(디브리핑) → 다음 단계에서 무엇을 왜 하나·사람이 할 일(브리핑). 비전공자가 읽고 「지금 어디인지」 알 만큼 쉽게. `docs/HANDOFF.md` 는 이 의식에서 쓰지 않는다 — 승계(`succeed`)·compact 직전·새 세션에 붙여 넣을 프롬프트를 만들 때만 `handoff` 로 쓴다. 시간·진행 위치 점검은 별도 세션 없이 이 의식이 맡는다.
- **AI 제안을 거절·수정한 순간**(사용자가 오케·워커·평가의 제안을 바꾸거나 오케가 평가·워커·보안 지적을 기각·일부 수용할 때) 단계 전환을 기다리지 않고 그 자리에서 `decision` 을 남긴다 — 「제안: 누가 → 채택·수정·거절」 줄과 이유 (채점: AI 제안의 채택·수정·거절 이유).
- **위임 장부·시간 앵커 기록 (사람 손 0)**: 오케가 `docs/PLAN.md` 「위임 장부」에 `brief` 발행·역할 탭 안내·서브에이전트를 띄울 때 행을 열고(탭 · 맡긴 일 · 모델을 고른 이유 · 예상 소요) 「<모듈> 끝」·역할 탭 「~ 끝」 신호 때 실제 소요·결과(통과/재작업 N)를 채운다. 「시간 앵커」 실제 시각은 앵커를 지나는 신호 턴에서 `date +%H:%M` 으로 채운다. **중복 위임 금지 — 같은 일을 두 탭/서브에이전트에 동시에 맡기지 않는다 — 맡기기 전 위임 장부를 본다.** 사용량 원칙: effort 는 일 난이도대로 차등(이유는 장부 칸에) · 키트·기존 산출물 재사용 · 컨텍스트가 차면 `succeed`.
- **기다리는 일은 서브에이전트**: 평가(구현 직전)·pathfind·리서치·독립 재계산처럼 결과만 필요한 일은 오케가 **Codex 서브에이전트로 병렬 스폰**하고 그동안 다음 일(다음 DM 질문 · 브리프 초안)을 한다. 서브에이전트는 자동으로 안 뜬다 — 「병렬로 띄우고, 모두 기다린 뒤 요약」(오케가 기다리는 일이면) 또는 「띄우고 기다리지 않는다」를 **명시**한다. 서브에이전트는 부모의 모델·effort 를 상속하므로 가벼운 일은 낮은 모델·effort 를 말해 준다. 쓰기가 겹치지 않게 파일 범위를 갈라 준다. DM 은 서브에이전트가 아니라 **전담 탭**(`roles/DM.md`)이 표준이다 — 오케와는 `docs/interview/요약.md` 파일로 공유하고, `codex queue` 가 되면 「요약 갱신 알림」 용도로만 선택한다.
- **위임 형식**: `brief` 스킬 3줄 틀(원인·범위 → 지킬 것 → 검증과 완료 조건). 완료 보고는 Verify 를 직접 돌린 뒤 받는다. 긴 작업은 예상 소요를 먼저 말한다.
- **승계 기준**: 같은 실패 2회 · 응답 지연 3배 · compact 2회째 — 마일스톤 경계에서 `succeed` 스킬로 새 오케스트레이터에 넘긴다. **빌드 중 승계 최소 1회**는 실제로 한다. 워커도 `succeed`(워커 모드)로 자기 `src/<모듈>/HANDOFF.md` 를 쓰고 새 탭에 넘긴다.
- **compact·승계는 단계가 넘어갈 때 오케스트레이터가 먼저 제안한다** — 기준은 컨텍스트 양이 아니라 **연결성**이다: 다음 단계가 이전 대화의 뉘앙스 없이 파일만으로 이어질 수 있으면(아래 권장 지점) 단계 전환 응답 끝을 `다음 입력(오케): /compact` 또는 `다음 입력(오케): $succeed` 로 내고 한 줄로 이유를 단다. 승계 기준에 걸려도 같다. 컨텍스트 양 관리는 사용자가 상태줄을 보고 직접 한다 — 오케스트레이터는 컨텍스트 수치를 묻거나 추정하지 않는다. 사람이 먼저 떠올리길 기다리지 않는다.
- **compact**: 상태가 전부 파일에 들어간 순간에만, 직전에 `handoff`. 권장 지점(강제 아님): 오케스트레이터 M2 설계 확정 뒤·브리프 발행 직후 = **승계**(빌드 중 승계 1회를 여기서 채운다 — 구현 탭은 브리프만 읽으므로 끊기지 않는다) · M4 끝·M5 전 = compact(승계 기준에 걸리면 승계). **M1→M2 사이는 compact 하지 않는다**(설계에 실무자 말의 뉘앙스가 필요). 워커는 compact 대신 새 탭. 평가·보안 탭은 일회용이라 하지 않는다.
- **compact 직후**: `AGENTS.md` + `docs/HANDOFF.md` + 현 단계 파일(`guides/STAGES/`)을 다시 읽고 재개한다.
- **구현 검수·재지시**: 워커 보고는 끝나는 순서대로 받는다 — 계약 테스트 초록 + `docs/ARCHITECTURE.md` 대조. 빠진 것은 그 브리프 맨 아래 「재지시」 절에 붙이고 사람은 그 탭에 「브리프 맨 아래 재지시 읽고 해」. 같은 지적으로 2번 실패하면 새 탭(지시를 고쳐서).
- **메모**: `docs/MEMO.md` 는 사용자 메모장(종이 대체) — 오케스트레이터는 읽지 않는다. 오케스트레이터는 매 턴 끝에 「지금 상황 2줄 + `다음 입력:` 한 줄」을 사용자에게 말한다.
- **서술형 연습 안내**: 문제 확정 · 설계 확정 · 모듈 끝 · 피드백 끝 응답에는 `그다음(설명): 서술형 연습하자` 를 덧붙인다(설명 탭이 질문 1개를 던진다 — `roles/설명.md`). 사용자가 쳐야 하는 건 아니고 설명 탭에 돌아올 때다.
